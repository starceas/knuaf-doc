# 오류·불편 신고 절차 (AI 행동 규칙)

학생이 "신고할래 / 불편해요 / 이런 기능 있었으면"이라고 말하거나, 명령 실패·예상과 다른 결과·반복되는 불편을 AI가 확인했을 때 이 문서를 따른다. 신고 초안·전송·영수증은 이 스킬의 `scripts/gg_report.py`를 현재 Python 실행기(`python3` 또는 Windows에서는 `py -3`)로 실행해 처리한다. 학생에게 명령·JSON을 요구하지 않는다.

## 권하기

한 번만 "개발자에게 신고할까요? 보내기 전에 내용을 보여 드립니다"라고 권한다. 거절하면 같은 사건으로 다시 권하지 않는다. 학생 작업을 멈추고 신고를 강요하지 않는다.

## 경로 — 비공개 하나

- 모든 신고는 `private`(개발자 비공개 채널) 하나로 보낸다. 입력의 kind는 언제나 `private`다. `issue`를 넣으면 스크립트가 `issue_channel_closed`로 거부한다.
- 신고는 개발자가 먼저 비공개로 받아 검토한 뒤, 필요하면 개인 정보를 뺀 공개 이슈로 개발자가 옮긴다. 학생이 공개 이슈를 직접 만들 일은 없다.
- 비공개 채널이므로 개인 사정(건강·가족·경제·학업 성적·교수·학교 관계·신원)이 얽힌 내용도 그대로 적을 수 있다. 다만 보내는 것은 학생이 미리보기로 확인하고 동의한 내용뿐이다.
- 이전 버전이 만든 공개 이슈 초안은 전송되지 않는다(이미 보낸 초안의 영수증만 확인한다). 그런 초안이 있으면 비공개 초안을 새로 만든다.

## 작성 (draft)

AI가 대화에서 증상을 일반적인 말로 요약해 입력 파일을 만들고, `python3 scripts/gg_report.py draft --input <in.json> --out <새초안.json>`을 실행한다. 입력 키는 kind(항상 `private`), category(bug|feature|inconvenience|other), title, description, 선택 steps·error_message뿐이다.

private에는 environment가 실려 가지 않으므로, 환경 정보가 필요하면 description에 직접 적는다. private는 제목·분류·본문·선택 필드를 합친 전달 문자열의 UTF-16 길이가 1,900을 넘으면 `private_too_long`으로 거부된다. 자르지 말고 더 짧게 요약한 새 초안을 만든다.

스크립트는 private 본문에서도 로컬 경로·이메일·전화·주민번호를 자동으로 가린다(`[경로 가림]` 등). 이름·학번·파일명·날짜 같은 숫자는 가리지 않는다 — 비공개 채널이라 진단에 필요한 값을 남기기 위해서다. draft 출력의 `redactions`를 보고 진단에 꼭 필요한 값(예: 오류가 난 파일 경로)이 가려졌으면 학생에게 알리고, "내 Documents 폴더 안 엑셀 파일"처럼 덜 구체적인 표현으로 다시 쓸지 묻는다. 가림을 우회하는 기능은 없다.

draft 출력의 `warnings`는 보내기 전에 한 번 더 확인하라는 표시다(전송을 막지는 않는다). private는 개인 사정이 필요할 수 있으므로, 학생이 미리보기를 보고 동의하면 그대로 보낸다.

## 확인과 전송 (show / send)

draft 출력의 `preview`를 바꾸지 않고 그대로 보여 주고 "이대로 보낼까요?"라고 묻는다. 명시적 동의(보내/네/좋아요 등)만 전송 동의로 본다. 고치자고 하면 새 초안 파일을 만들고 다시 보여 준다. 동의한 그 초안의 `sha256`으로만 `python3 scripts/gg_report.py send --draft <초안> --confirm <sha256>`을 실행한다. 보여 준 내용과 다른 바이트는 절대 보내지 않는다.

- `already_sent`: 이미 보낸 초안이므로 그 사실만 알린다.
- `delivery_unknown`: 전에 보내기를 시도했지만 접수 확인이 안 된 상태다. 자동 재전송하지 않는다. 중복으로 전달될 수 있음을 설명해 동의를 받은 뒤에만 `--retry-unknown`으로 다시 보낸다.
- `not_sent`·`rejected`: 이유를 쉬운 말로 알린다. `rate_limited`면 1분 뒤 다시 보낼지 묻고, 그 밖에는 고친 새 초안을 제안한다. 자동 반복 재시도는 하지 않는다.
- `sent`·`sent_unrecorded`: 비공개로 전달된 사실을 알린다. `sent_unrecorded`도 실제로는 접수된 것이다.

## 파일 위치

초안·전송 claim·영수증은 학생 작업 폴더의 `reports/` 아래 새 파일로만 만든다(예: `reports/report-YYYYMMDD-HHMMSS.json`). 작업 폴더가 없으면 임시 폴더를 쓴다. 정본(project.json)·원고·이 저장소의 파일은 신고 과정에서 만들거나 고치지 않는다.

## 한계

- 전송 대상은 배포된 수신 Worker 하나로 고정된다. 시험용 주소는 초안에 기록돼 미리보기에 "[시험 대상]"으로 표시된다.
- 멱등성은 이 컴퓨터의 같은 초안 파일 기준이다. 수신 측에 중복 방지 키가 없어 서버 측 "정확히 한 번"은 보장하지 않는다.
- 자동 가림은 로컬 경로·이메일·전화·주민번호 네 가지뿐이다. 이름·학번·파일명 같은 값은 그대로 전달된다 — 비공개 채널이라 진단에 필요해서다. 학생 미리보기 확인이 최종 방어선이다.
- 네트워크를 쓸 수 없는 환경(채팅 전용 등)이면 미리보기만 보여 주고 "보내지 못했다"고 말한다. 전송 완료라고 말하지 않는다.
