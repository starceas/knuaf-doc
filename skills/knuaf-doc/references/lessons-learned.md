# 실작업 교훈 (2026-09-02 밭매고 논문 1차 빌드에서 축적)

다음 논문을 처음부터 쓸 때 같은 실수를 반복하지 않기 위한 기록이다.

## L1. 공식 목차를 먼저 고정하고 쓴다
본문을 다 쓴 뒤에 목차 불일치를 발견하면 재편 비용이 크다.
착수 즉시 `official-toc.md`(존재 시)의 뼈대를 파일로 만들고 절을 채워 나간다.

**실제 발생**: Ⅱ장을 5개 절로 평평하게, Ⅲ장에서 SWOT을 독립 절로 썼다가
공식 목차(Ⅱ는 대분류 2개, SWOT은 2-마 하위)와 어긋나 재편이 필요했다.

## L2. 원본 HWP 추출은 수단을 확인하고 시작한다
`hwp5txt`가 설치되지 않은 환경이 있다. 설계 세션에서는 Kordoc MCP를 썼다.
인자명이 `file_path`다(`path` 아님). 목차·표 구조까지 함께 나온다.

## L3. 작목 선정은 재무 게이트를 먼저 통과시킨다
작목을 정하고 본문을 쓰기 시작하면 나중에 적자가 드러났을 때 전부 버려야 한다.
**순서: 인터뷰 → 작목 후보 조사 → 재무 역산 → 흑자 확인 → 그때 본문 착수.**

**실제 발생**: 병풀로 상당 분량을 진행한 뒤 구조적 적자(최소 -1,710만원)가 확인돼
작목을 교체했다. 이후 쌈채소로 갔다가 전공 부적합으로 다시 새싹삼으로 교체했다.

## L4. 작목은 전공 정합성을 먼저 확인한다 (→ interview-guide.md Q2로 승격)
재무가 좋아도 전공에 맞지 않으면 심사에서 반려된다.
- 특용작물전공: 약용작물·버섯류·인삼류·허브·차류·유지작물·기호작물
- **제외**: 엽채류(상추·쌈채·청경채), 과채류(딸기 = 원예학과 소관)
- **주의**: 버섯은 별도 전공이 있는 학교에서는 특용작물전공 논문 주제로 부적절할 수 있다
- 재배기간이 긴 약용작물(도라지·더덕 2~3년)은 단위면적 조수입이 감가상각에 미달하기 쉽다

## L5. 하위모델 조사 결과는 반드시 재검산한다
조사 위임은 효율적이지만 **수치를 그대로 믿으면 안 된다.** 실제로 잡아낸 오류들:

- **이중계산**: "다단 재식밀도 × 회전수"를 곱해 연 600만 주, 매출 28억이 나왔다.
  베드 순면적 기준과 농장 바닥면적 기준을 혼동한 것. 실측 농가 사례로 역산해 교정했다.
- **비용 누락**: 표고버섯 조사가 인건비 0원, 수선유지비 0원, 유효면적률 100%로 계산해
  "1년차 5,220만원 흑자"라 했으나 재검산하니 -691만원 적자였다.
- **자기모순**: 같은 답변 안에서 ㎡당 8,976주와 1,400주가 6배 차이로 공존했다.

**대응**: 조사 프롬프트에 "이전에 이런 오류가 있었다"를 명시하고,
"네가 제시한 수치가 실제 농가 규모로 현실적인지 스스로 검산하라"를 요구한다.
받은 뒤에는 반드시 직접 계산해 대조한다.

## L6. 생산능력이 아니라 판로에서 역산한다
"얼마나 만들 수 있는가"가 아니라 **"얼마나 팔 수 있는가"**가 규모를 결정한다.
시장 규모 대비 점유율을 계산해 현실성을 확인한다(신규 농가는 1~3%가 상한선).

**실제 발생**: 새싹삼 풀가동 시 연 900만 주가 나오는데 국내 시장 전체가
3,500만~5,000만 주였다. 시설을 150평으로 줄여 연 82.5만 주(점유율 2.4%)로 맞췄다.

## L7. 기후 데이터는 시설 설계를 바꾼다
지역 최고기온을 확인하지 않고 시설비를 잡으면 나중에 전면 재계산해야 한다.
작목 생육적온과 지역 극값을 대조해 냉난방 설비를 **초기 투자에 포함**시킨다.

**실제 발생**: 김해 2024년 최고 39.4℃ vs 새싹삼 적온 15~20℃.
냉방 3종을 추가하며 시설비가 2.25억→2.9억으로 올랐고 흑자 시점이 밀렸다.

## L8. 정부 지원금은 손익과 현금흐름을 분리한다
영농정착지원금 같은 바우처는 **사업소득이 아니다.**
손익계산서에 넣으면 영업 실적을 부풀린 것처럼 보인다.
→ 손익에서 제외하고 현금흐름과 대차대조표 자본(이익잉여금)에만 반영한다.
→ 본문에 "왜 이렇게 처리했는지"를 명시하면 오히려 신뢰를 얻는다.

## L9. 엑셀은 soffice 재계산 검증이 필수다
openpyxl은 수식을 계산하지 않는다. 눈으로는 못 잡는 오류들:

- 기초차입금이 기말(10행) 대신 원금상환(8행)을 참조 → 2년차부터 이자 폭락
- 연차 헤더가 잘못된 행을 참조 → 거치기간 판정 실패, 거치 중 원금상환 발생
- 지원금이 자산에만 반영되고 자본 미반영 → 대차 불일치
- 병합 밴드가 데이터 행과 충돌 → MergedCell read-only 예외

**검증 절차**: `soffice --headless --calc --convert-to xlsx --outdir <dir> <file>` 후
`data_only=True`로 읽어 독립 십진 계산의 출력 단위·반올림 결과와 대조한다. 비율 오차를 허용하지 않는다. 캐시 없음과 수식 오류는 미검증/실패다.

## L10. 서브에이전트에 참고 파일 전체를 읽히지 않는다
xlsx 2개를 통째로 읽히다가 컨텍스트 초과로 에이전트가 두 번 죽었다.
구조 정보는 미리 조사해 **프롬프트에 텍스트로 넣고**, "참고 파일을 열지 마라"를 명시한다.

## L11. agy(Gemini) 실행은 전경 TTY로 한다
이 환경에서 `nohup`/`setsid` 백그라운드 실행이 파일을 생성하지 못했다.
`tty:true`로 전경 실행하고 `tee`로 파일에 남긴 뒤, 폴링으로 완료를 감지한다.
exec 셀은 30초에 잘리므로 폴링 루프를 여러 번 돌린다.

## L12. 본문 수치는 기계 검사로 대조한다
사람 눈으로는 놓친다. 확정 가정표의 수치 목록과 폐기 수치 목록을 만들어
정규식으로 대조하는 스크립트를 돌린다. 가정이 바뀌면 전 장을 재검사한다.

**주의**: 오탐이 나온다. "쌈채소"가 폐기 작목 잔재가 아니라
"잎을 쌈채소처럼 먹는다"는 정상 서술인 경우가 있었다. 발견 시 문맥을 확인한다.

## L13. 한 경로가 막히면 이미 쓰던 대체 경로부터 확인한다
웹 검색 도구가 429(사용량 한도)로 막히자 "검증 불가"로 판단하고 사용자에게
판단을 넘겼다. 그러나 같은 세션에서 이미 여러 번 쓰던 agy(Gemini) 위임 경로가
멀쩡히 살아 있었고, 위임하니 논문 5편이 전부 즉시 검증됐다.

**규칙**: 도구 실패를 작업 불가로 성급히 등치시키지 않는다.
막히면 (1) 같은 목적을 수행할 다른 경로를 먼저 나열하고 (2) 실제로 시도한 뒤
(3) 전부 실패했을 때만 사용자에게 보고한다.
이 스킬에서 웹 조사 경로는 최소 3개다: 자체 검색 / agy(Gemini) 위임 / Aside 브라우저.

## L14. 논문·서지사항은 반드시 실재 검증한다
하위 모델이 제시한 논문은 저자·학술지·권호·페이지가 그럴듯해도 실재를 보증하지 않는다.
**별도 호출로 KCI·DBpia·KoreaScience·DOI를 조회해 교차검증한 뒤에만 인용한다.**
심사위원이 전공 교수라면 실제로 찾아볼 가능성이 높고, 존재하지 않는 논문 하나가
논문 전체의 신뢰를 무너뜨린다.

검증 프롬프트에는 "실재확인 / 부분확인 / 확인불가" 3단 판정을 요구하고,
"못 찾으면 못 찾았다고 하라, 지어내서 메우지 마라"를 명시한다.

## L15. 참고 자료의 작성 시점을 먼저 확인한다

선배 논문을 분석하다가 그 목차 배치를 현행 규칙의 근거로 삼을 뻔했다.
확인해보니 **선배 논문이 작성요령보다 먼저 작성된 문서**였다(2019년 12월 vs 2020년 4월).
오래된 사례가 새 규칙의 근거가 될 수는 없다.

**규칙**: 참고 자료를 근거로 쓰기 전에 작성·제출 시점을 확인한다.
- 규칙 문서보다 앞선 자료 → 목차·절 구성·서식의 근거로 쓰지 않는다
- 가져올 것: 글의 흐름, 분량 감각, 서술 깊이, 표·그림 밀도
- 가져오지 않을 것: 절 번호 체계, 목차 구성, 서식 규정

교수가 칭찬한 논문이라는 사실도 그 논문의 목차가 현행 규칙이라는 뜻이 아니다.
칭찬의 대상은 대개 내용의 깊이와 논증이지 양식이 아니다.

## L16. 원본 규칙의 빈틈을 임의로 메우지 않는다

작성요령은 학교에서 만든 문서라 내부 충돌과 오기가 있다.
실제로 확인된 것: 모델농장·SWOT의 장 배치 충돌(Q9), 제목 번호 글자크기 오기(Q10),
연도 예시가 고정값처럼 보이는 문제(Q11).

**이런 빈틈을 우리가 '이게 맞을 것'이라고 판단해 메우면 규칙이 아니라 추측이 된다.**
- open-questions.md로 격리하고 교수 확인 항목으로 남긴다
- 잠정 기본값을 쓸 때는 그것이 편의상 선택임을 명시한다
- 규칙으로 명시된 것만 정확히 지킨다. 명시되지 않은 것을 규칙처럼 다루지 않는다

## L17. 참고 엑셀은 XML로 읽는다

참고본 2종은 openpyxl로 열면 `IndexError: list index out of range`(스타일 인덱스)가 난다.
구조 분석이 필요하면 `zipfile`로 `xl/worksheets/sheetN.xml`을 직접 파싱한다.
sharedStrings.xml에서 문자열을, `<f>` 태그에서 수식을 얻는다.

그리고 **분석 결과를 문서로 남긴다.** 매번 파싱하면 컨텍스트를 낭비하고,
서브에이전트에 위임하면 통째로 읽다가 죽는다(실제 2회 발생).



## L18. 기상 자료 조사 — 단일 엔드포인트 수집과 결측 보존 원칙 (2026-09-18, 함안 사례)

### 발생한 오류와 원인
1. **위임 모델의 추정값 오보고**: gemini-3.8-flash가 검증상태 "확인"으로 보고했으나 창원 기온 오기(15.0℃는 부산 값, 실제 14.8℃), 함안 AWS 지점번호 착오(255/612가 아닌 920 가야읍 산서리), 함안 단독 평년값 부존재(평년값 자체 미산출 지점) 등 허위 판정 발생.
2. **관측소 전제 착오**: 함안군에는 종관기상관측소(ASOS)가 없고 방재기상관측(AWS)만 존재. 30년 평년값은 ASOS 중심이므로 함안 단독 평년값은 없으며 인근 ASOS인 창원(155)·진주(192)를 참조해야 함.
3. **최고·최저기온 의미 혼동**: 기상청 표의 최고·최저기온은 극값이 아니라 **연평균 최고기온·연평균 최저기온**임. 이를 극값처럼 서술하면 오류.
4. **서리 관측 지점 오판**: 서리 목측은 유인관서에서만 수행되며 진주(192) 등 무인 지점은 측정 불가.
5. **동적 포털 껍데기 오해**: 기상자료개방포털 통계 화면(`grndSnowList.do` 등)은 정적 GET 시 1,872바이트 빈 껍데기를 반환함. '자료 없음'이 아니라 JS 동적 렌더링 필요 상태임.
6. **검사기 인식 구조**: 본문 산문에 "해당 항목은 미확인"이라고 써도 `climate_fields` 검사는 통과 못 함. 항목명이 **표의 행으로 반드시 존재해야** 인식함.
7. **서브에이전트 위임 3회 연속 실패**: grok-4.6에 위임 시 한국기후표 PDF 파싱에 매달리다 빈 산출물(200~600B)만 남기고 세션 종료.

### 단일 수집 해결 경로 및 헌법
- **1차 단일 수집**: 기상 항목은 처음부터 `weather.go.kr` 지역 기후 단일 페이지를 직접 GET 수집한다.
  ```bash
  curl -sL "https://www.weather.go.kr/w/climate/statistics/region.do?area=7"
  ```
  이 84KB 단일 페이지에서 해당 권역 지점별 평년값 표(평균/최고/최저기온, 습도, 강수량, 풍속)와 계절별 기후특성까지 한 번에 확보한다.
- **결측치 표기 원칙**: 확보하지 못한 항목(월별 평년값, 적설, 주풍향, 극값, 서리일수 등)은 **표의 행을 그대로 유지**한 채 값만 `미확인`으로 두고 사유를 서술한다. 절대 N/A로 바꾸거나 행을 삭제하지 않는다.
- **조사 위임 원칙**: 기상 조사가 진행 메시지만 남기고 끝나면 재시도하지 말고 메인이 직접 curl 수집으로 전환한다. 타 모델의 조사 결과는 원문 교차검증을 통과한 것만 엄격 채택한다.
