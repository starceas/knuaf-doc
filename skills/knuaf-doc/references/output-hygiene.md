# 산출물 정리 규칙

논문 하나를 쓰는 동안 최종본과 시험물을 구분한다. 이 문서가 정리 규칙의 정본이다.

## 최종본은 산출물마다 한 경로

- 사람이 받는 최종본(재무 엑셀, 논문 워드/한글, 같은 엑셀의 PDF)은 산출물마다 한 경로에만 둔다. 이름에 회차(`_F2`, `_v3`, `-final2`)를 붙이지 않는다.
- 새 최종본이 나오면 같은 이름으로 교체한다. 이전 최종본은 옆에 남기지 않고 `.gg-work/<산출물이름>/<회차>/`로 옮긴다(삭제하지 않는다).
- 짝 파일은 최종본과 같은 이름·같은 폴더에 둔다.
- 적용 범위: 이 교체 규칙은 **사람이 받는 사본**에만 적용한다. `.gg-artifacts/`·`build/<revision>/<kind>/`의 관리본·수령증은 옮기거나 덮어쓰지 않는다. `gg.py import <기존폴더> --out <새폴더>`의 목적지는 독립 작업폴더이므로 `.gg-work` 안으로 바꾸지 않는다.

## 중간 산출물은 `.gg-work/` 한 곳

- 시험·중간 파일(pre/copy/filled, fill-map/print-map/fill-values JSON, 영수증, native PDF, 작업용 원본 사본 `blank`·`template-original`)은 `.gg-work/<산출물이름>/<회차>/` 아래에 쓴다. 회차 이름은 `r001`, `r002`… 순번이다.
- 작성 폴더나 산출물 폴더 최상위에 `build-fN`, `evidence-fN`, `runN`, `*_FN.xlsx` 같은 형제 폴더·파일을 만들지 않는다.
- 세션 자체의 발주·보고·검토 문서(ORDER/REPORT/REVIEW 등)는 `.gg-work/notes/`에 둔다.
- 스크립트의 `--out-dir`/`--out`에 중간 결과를 받을 때 `<새폴더>`는 이 경로를 뜻한다. `build/`는 기존 스크립트 계약(publication·export)이므로 바꾸지 않는다.

```text
작성폴더/
  재무계획_2027-2031.xlsx      ← 최종본 1개
  재무계획_2027-2031.pdf       ← 같은 이름의 짝
  논문_최종.docx               ← 최종본 1개
  build/                       ← 기존 발행 계약
  .gg-work/
    재무계획_2027-2031/
      r001/                    ← 이전 회차(정리 후보)
      r002/                    ← 최신 회차(보존)
    논문_최종/
      r001/
    notes/
      ORDER.md
```

## 정리 명령 `gg.py tidy <작성폴더>`

기본은 미리보기다. 지울 후보·남길 것(사유)·용량을 출력하고 아무것도 바꾸지 않는다. `--apply`일 때만 삭제한다.

```sh
python3 scripts/gg.py tidy <작성폴더>
python3 scripts/gg.py tidy <작성폴더> --apply
```

삭제 후보는 `.gg-work/<산출물이름>/<회차>/` 회차 폴더 단위로만 정한다. 다음 중 하나라도 해당하면 남긴다.

1. 그 산출물의 가장 최근 회차(회차 번호가 가장 큰 `r<숫자>` 폴더) 1개.
2. 회차 폴더 안에 `.keep` 파일이 있음.
3. **참조 중**: 작성 폴더 안의 JSON 파일 어디든 그 회차의 상대경로(`.gg-work/<산출물>/<회차>/`)나 그 안 파일 경로를 문자열로 담고 있음. 경로 구분자 `/`와 `\`는 같은 경로로 본다. 후보 자신의 JSON은 제외한다. 읽기 실패·해석 불가 파일이 경로 문자열을 담고 있으면 남긴다.
4. `notes/`, 회차 규칙 밖 이름(직접 만든 폴더 등)은 건드리지 않는다.

`--apply`는 기존 `gg_lock.Lock(<작성폴더>)`를 잡은 상태에서 후보·보존 조건을 다시 계산하고 삭제가 끝날 때까지 점유를 유지한다. 잠금 프로토콜이 없거나 손상·복구 중·다른 작업자가 점유 중이면 변경 없이 거부한다(자동 설치·복구로 우회하지 않는다). 참조 검사 중 읽지 못한 폴더가 있으면(권한 등) 미리보기에 `scan_errors`로 표시하고 `--apply`는 `reference_scan_incomplete`로 변경 없이 거부한다. `.gg-work/` 밖은 절대 지우지 않는다. 밖에 있는 회차형 이름(`build-*`, `*_F\d+*` 등)은 작성 폴더 아래 하위 폴더까지 같은 이름 규칙으로 "정리 후보(자동 삭제 안 함)"로 보고만 한다. 보고는 작성 폴더 기준 상대경로이며, `.gg-work`·`.git`·`.gg-lock`·`.gg-recovery`·`__pycache__` 아래는 훑지 않고 후보로 잡힌 폴더 안으로 더 들어가지 않는다. 심볼릭 링크는 보고만 하고 따라가지 않는다. 이 훑기에서 읽지 못한 폴더는 `outside_scan_errors`로 표시하며 삭제와 무관하므로 `--apply`를 막지 않는다. 심볼릭 링크는 따라가지 않고 그 회차를 남긴다.

## 세션 규칙

- 최종본을 교체·검증한 직후 `tidy` 미리보기를 실행하고, 사용자 확인 뒤에만 `--apply`한다.
- 잠금을 쓰지 않는 다른 세션이 같은 작성 폴더에서 시험 중이면 `--apply`하지 않는다. tidy는 그 세션의 활성 회차를 알 수 없다. 이 확인은 세션 몫이며 명령이 막지 못한다.
