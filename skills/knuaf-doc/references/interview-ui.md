# 인터뷰 질문 제시 방식

**모든 질문은 채팅 텍스트로 제시하고 사용자가 채팅으로 답한다.**
환경(Codex 앱 / 터미널)에 따라 나누지 않는다. 하나의 방식으로 통일한다.

## 왜 텍스트인가

선택지 팝업(`request_user_input`)은 Plan 모드에서만 제공되고 터미널에는 없다.
환경마다 다르게 동작하면 배포본에서 예측이 어렵다.

더 중요한 이유가 있다. **팝업은 닫히면 대화에 기록이 남지 않는다.**
이 스킬은 인터뷰 원문을 원답변 파일에 그대로 보존하고 해당 파일을
`project.json.sources`에 등록하는 것을 전제로 한다. 채팅 텍스트로 주고받으면
질문과 답이 대화에 그대로 남아 기록과 어긋나지 않는다.

    질문(텍스트) → 답변(채팅) → 로그 기록

터미널에서도 화면이 깨지지 않도록 **표·굵은글씨를 쓰지 않는다.**

## 공통 원칙 — 질문 형태 3종

답변 성격에 따라 형태를 고른다. 아무 질문이나 자유서술로 던지지 않는다.

### 1) 선택형 — 답이 정해진 범위 안에 있을 때

창업형/승계형, 매입/임차, 어투 선택처럼 **경우의 수가 적은 것.**

```학생화면
[Q2-3] 부지 확보 방식 · 자산 조사(Ⅳ-1)에 쓰여요

부지는 어떻게 확보할 계획인가?

  1) 매입
  2) 임차
  3) 가족 소유 사용
  4) 아직 미정  ← 조사해서 지역 시세와 함께 제시하겠다

번호로 답해도 되고, 사정이 있으면 그대로 적어도 된다.
```

**규칙**
- 보기는 2~5개. 그 이상이면 사용자가 못 고른다
- **마지막 보기는 항상 `미정`**이고, 고르면 무엇을 해줄지 함께 적는다.
  답변의 저장·재사용·질문 종료는 [workflow-order.md](workflow-order.md)를 따른다.
- 번호 외 자유 입력도 받는다고 명시한다. 보기에 없는 사정이 흔하다
- 식량작물(`food_crops`)의 갈래 질문(승계/창업, 단작/이모작)도 이 선택형 형식을 따른다.

### 2) 값 입력형 — 숫자·고유명사

면적, 금액, 농장명처럼 **사용자만 아는 값.**

```학생화면
[Q2-2] 자금 · 재무 계획(IV장)에 쓰여요
준비된 자기자본과 융자는 얼마인가요?
예: 자기자본 5,000만원, 청년후계농 융자 1억 5,000만원
→ 금액을 직접 적어 주시거나, 모르면 "미정"이라고 답해 주세요.
```

**규칙**
- 단위를 명시한다. 평과 ㎡를 섞으면 계산이 틀어진다
- 예시를 1~2개 준다. 형식을 몰라 멈추는 것을 막는다
- "미정"도 유효한 답이라고 알린다
- 금액·면적처럼 직접 적어야 하는 값은 보기로 만들지 않고 질문 한 줄과 예시 한 줄로 묻는다.
- 초반 [Q2]의 자금 칸을 제외한 별도 금액 질문에는 번호 하위 항목을 붙이지 않는다. 자기자본과 융자를 나눠 적는 예시 한 줄을 준다.

### 3) 서술형 — 생각·이유

비전, 작명 배경, 애로사항처럼 본문 구성의 글감이 되는 답변이다.

```학생화면
농장명을 짓게 된 배경을 알려달라.
(관련 소개 절의 글감으로 사용한다. 짧게 답해도 된다)
```

**규칙**
- **어느 절에 쓰이는지 알린다.** 사용자가 성의 있게 답할 이유가 된다
- 짧은 답도 받으며 완성 문장이나 정해진 분량을 요구하지 않는다
- 답이 막연하면 되묻지 말고 **예시를 만들어 보여주고 고치게 한다**

## 질문 화면 형식

한 화면에 들어오게 쓴다. 터미널과 앱 어디서나 같은 형식을 쓴다.

```학생화면
[Q2-3] 부지 확보 방식 · 자산 조사(IV-1)에 쓰여요
농사지을 부지는 어떻게 확보하시나요?
  1) 매입
  2) 임차 (추천) — 초기 시설 투자에 집중
  3) 가족 소유 농지 사용
  4) 아직 몰라요 — 익산 임차 모델로 제안할게요
→ 번호로 답하거나 직접 적어 주세요.
```

**규칙**
- 학생에게 보이는 모든 글(진행 메시지 포함)에 `project.json`·정본·`import`·프로세스·잠금·revision·fact·claims 같은 내부 말이나 Kordoc 같은 도구 이름, 바인딩·개정·격리·RDA 팩·18시트·영수증 사슬·지도·`field_id` 같은 작업 용어를 쓰지 않는다. “작업 기록”, “복사본”, “지금 쓰는 원고”처럼 쉬운 말로 바꾼다. 진행 메시지에는 이 학생의 전공만 쓰고 다른 전공 이름이나 전공끼리 비교하는 말은 쓰지 않는다. 검사가 멈춘 이유를 알릴 때는 결과 코드 대신 [학생 말 표](outputs.md#검사-결과를-학생-말로)를 쓴다.
- **한 메시지에 질문 하나**만 한다. 예외는 첫 `[Q2]`에서 기본 계획의 여러 칸을 한 질문으로 묻는 경우뿐이다. Q1a 현재 작성물과 Q1b 참고자료는 같은 메시지에서 묻지 않는다. 자료 주인과 전공처럼 서로 다른 확인도 따로 묻는다. 여러 정보가 필요하면 가장 먼저 막히는 하나만 묻는다. 진행 메시지에서 예고한 다음 질문과 실제 질문은 같아야 한다.
- 문항 번호를 앞에 단다. 로그에서 역추적할 때 필요하다
- 표·굵은글씨를 쓰지 않는다. 터미널에서 깨진다
- 초반 `[Q2]`만 아직 모르는 기본 계획 항목을 한 질문 안의 여러 칸으로 묻는다.
- 선택형 질문은 반드시 `[Qn-m]`으로 표시한다. `[Q2]`는 선택형이 아닌 여러 칸 질문에만 쓴다. 번호는 숫자 두 단계까지만 쓰고 세 단계나 글자 접미는 쓰지 않는다. 보기는 `1)` 형식으로 쓴다.
- 선택형 질문은 보기 위에 물음표로 끝나는 한 문장, 25자 안팎으로 쓴다. 이유·배경은 넣지 않는다.
- 쓰이는 곳은 제목 줄 뒤에 ` · 표지·머리말에 쓰여요`처럼 짧게 적는다.
- 보기는 12자 안팎으로 쓴다. 설명이 꼭 필요하면 ` — ` 뒤에 15자 안팎으로 적는다.
- 추천안에는 `(추천)`을 붙일 수 있으나 전공에는 어떤 경우에도 추천을 붙이지 않는다. 작목만 먼저 알려준 경우도 같다.

### 진행 상황 표시

질문이 길어지면 얼마나 남았는지 보이지 않는다. 3문항마다 한 줄 넣는다.

```학생화면
확정 5 / 시범값 1 / 미확정 2  ─ 남은 것: 토지 명의, 판로
```

## 답변을 받은 뒤

1. 질문한 바로 그 항목에 대한 답인지 살핀 뒤, 그 항목의 해석만 짧게 되읽어준다 — "매입, 본인 명의로 이해했다"
2. 답이 다른 항목에만 맞거나 질문에 맞지 않으면 그 항목의 답으로 기록하지 않고 같은 질문을 한 번 쉽게 다시 묻는다(질문 횟수 한도 안).
3. 틀렸으면 즉시 정정받는다.
4. 원문과 해석을 함께 원답변 파일에 보존하고, 파일을 `project.json.sources`에
등록한 뒤 관련 fact/source/task 정본 기록에 `gg.py apply`로 연결한다
5. 선택형에서 번호만 받아도 원답변에는 보기 내용을 풀어 적는다. "2)"만 남으면 나중에 무슨 뜻인지 알 수 없다.

## 하지 않을 것

- 선택지 팝업을 쓰려 하기 (환경에 따라 없고 기록이 남지 않는다)
- 한 화면을 넘는 보기 나열
- "자유롭게 말씀해주세요"만 던지기 — 막연한 사용자는 여기서 멈춘다
- 모른다는 답에 같은 질문 반복하기
