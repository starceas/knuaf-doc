## 0값 681칸을 지워도 되는 근거

`clear` 안에 값이 0인 칸이 681개다. 0을 지워 공란으로 만들면 계산이 달라질 수
있으므로 원본 수식을 전수 해석해 확인했다(`survey/e-fix/r3/census.json`,
22,828개 수식 전부 파싱, 실패 0).

- 쓰인 함수는 **SUM 3,181 · ROUNDUP 72 · ROUNDDOWN 72 · PMT 4 · LOG 2 ·
  AVERAGE 1** 뿐이다. `COUNT`·`COUNTA`·`COUNTBLANK`·`COUNTIF`·`ISBLANK`·
  `ISNUMBER`·`IF`·`VLOOKUP`·`HLOOKUP`·`LOOKUP`·`MATCH`·`INDEX` **0개**,
  빈 문자열(`""`) 비교 **0개**, 글 리터럴 **0개**.
- 그래서 0과 공란을 구별하는 수식이 없다. `SUM`은 공란을 0으로 더하고,
  `ROUNDUP`/`ROUNDDOWN`/`PMT`/`LOG`는 인자가 공란이면 0으로 계산한다.
- `AVERAGE` 1개는 `clear` 칸을 인자로 읽지 않는다. `clear` 칸이 COUNT류·공란
  판별·조회 인자에 **직접** 들어가는 경우도 0칸이다.
- 시험이 이 함수 목록과 `""` 부재를 원본 실물에서 잠근다. 학교가 양식을
  개정해 함수가 늘면 이 근거를 다시 봐야 한다는 경보가 된다.

## 빈 사본에서 예상되는 `#DIV/0!` — 고장이 아니다(자체 재계산 기준)

사본의 수식 캐시는 전부 무효화되고(`formulaCachesInvalidated` **22,828**) 통합문서는
`fullCalcOnLoad`로 저장된다. 실제 수식(`<f>` 원소)은 **22,828개**다. 셀 값이
`=`로 시작하는 칸을 세면 22,829개가 되는데, 남는 1칸(`5.종부검정혈통등록비!E10`)은
`=` 한 글자뿐인 텍스트 칸이라 수식이 아니고 캐시 무효화 대상에서도 빠진다.

원본과 빈 사본(이 지도의 `clear` 칸을 공란으로 둔 것)을 같은 재계산기로 계산해
비교했다. 재계산기는 엑셀이 아니라 이 양식이 쓰는 문법(사칙연산·거듭제곱,
SUM·ROUNDUP·ROUNDDOWN·PMT·LOG·AVERAGE, 칸·범위 참조)만 해석하는 자체 계산기다.
그 원본 계산값이 실제 수식 22,828칸 **전부**에서 엑셀이 저장해 둔 값과 일치한다.
원본에는 오류 칸이 없고, 빈 사본에서만 `#DIV/0!`가 되는 칸은 **29개**다.
이것은 **자체 재계산으로 예상한 목록**이지 엑셀로 열어 확인한 목록이 아니다.

양식의 수식 하나(`10.감가상각비★★★` 시트)는 `R47:N47:N47:Q47`처럼 콜론이 여러 번
이어진 비표준 범위를 쓴다. 재계산기는 이것을 외곽 직사각형 `N47:R47`로 읽었고,
그 칸의 원본 계산값이 엑셀 저장값과 같았다. 다른 모양의 비표준 범위가 생기면
이 해석을 다시 확인해야 한다.

| 2026~2031 | `E190` | `=ROUNDUP(E192/2,0)-E206` | 암수 절반 가정 | 해당 시 | 두수 |
| 2026 | `Q246` | `=3500000*Q245` | 송아지 350만원. **2027~2031에는 이 칸이 없다** | 해당 시 | 매출 |
| 16-1.투자분석자료 | `H13` | `=1336/3` | 면적 환산 | 해당 시 | 투자분석 |
| 4.평균생산비 / 11.원리금상환계획 | `D12` / `C91` | `=0` | 수식인데 0 | 그대로 둔다 | — |

### 3. 사료프로그램 행 8은 같은 값을 두 방식으로 적었다

`거세비육 사료프로그램!F8`은 `=F5*F7*0.01`(7행 급여율 %를 읽는다)인데
`G8`은 `=G5*0.025`(상수를 박았다). `번식우 사료프로그램!G8`도 `=G5*0.025`다.
**7행 급여율을 고쳐도 G8 이후는 안 바뀐다.** 급여율을 바꾸려면 8행 수식의
상수도 같이 고친다.

### 4. 젖소(착유) 학생에게 이 양식은 한우 견본이다

이 28시트 양식은 한우(번식·비육·일관) 기준이다. 품종·암수·축사구조 같은
`input.student_text` 12칸은 빈 사본에서 비워지므로 **새로 적는다**. 착유 수입
행은 양식에 없다(범위 밖). 젖소 학생은 이 양식을 그대로 쓸 수 없고, 학교에
젖소용 양식이 있는지 확인해야 한다.

## 영수증에서 읽는 것

`blank_copy`가 내는 값. 시험은 실물 원본에서 직접 확인한다.

| 키 | 기대 | 뜻 |
|---|---|---|
| `cleared` | 1,070 | 지운 칸 목록(주소·이전 값) |
| `preserved` | 5,463 | 남긴 칸 목록(주소·이유) |
| `unclassifiedNumericCells` | 0 | 지도에 없는데 숫자가 남은 칸 |
| `unclassifiedTextCells` | 0 | 지도에 없는데 글이 남은 칸 |
| `formulaCellsProtected` | 0 | `clear` 대상과 수식이 겹친 칸 |
| `missingCells` | `[]` | 지도에 있는데 원본에 없는 칸 |
| `formulaCachesInvalidated` | 22,828 | 무효화한 수식 캐시 수(= 실제 수식 칸 수) |
| `output.status` | `blank_template` | 위 값이 모두 깨끗할 때만. 하나라도 어긋나면 `partial` |
| `workbook_profile` | `dairy_hanwoo_28_sheet_v1` | 지도가 선언한 프로필과 요청 프로필이 같아야 한다 |

`formulaCachesInvalidated`가 **22,828**인 것은 수식이 하나 모자라서가 아니다.
`5.종부검정혈통등록비!E10`은 값이 글자 `=`인 **텍스트 칸**이다(공유 문자열).
셀 값을 보고 "=로 시작하면 수식"으로 세면 22,829가 되지만, 실제 수식 원소
(`<f>`)는 22,828개다. 도구는 실제 수식을 세므로 22,828이 맞다.

## 거절되는 경우

지도와 요청이 어긋나면 사본을 만들지 않고 파일도 남기지 않는다.

- 지도의 `workbook_profile`을 다른 프로필로 바꿔 요청하면
  `unsupported_finance_profile`. 16시트 지도로 28시트 문서를 지우면 좌표가
  전부 어긋나므로 프로필 이름이 곧 레이아웃 검사다. 반대도 같다 — 다른 전공이
  `dairy_hanwoo_28_sheet_v1`을 요청해도 거절한다.
- 원본 구조가 등록된 지문과 다르면 `workbook_structure_mismatch`(메시지에
  `fingerprint`). 시트 순서·이름·시트별 수식 지문을 28장 전부 대조한다.
- 지도의 `source.sha256`과 실제 원본이 다르면
  `RuntimeError("source version changed")`. 학교가 양식을 개정하면 지도를 다시
  검토해야 한다.

## 사본 만드는 명령

```sh
python3 skills/knuaf-doc/scripts/gg_excel_template.py clear \
  --project <프로젝트 폴더> --major dairy \
  --source <학교 원본 xlsx> \
  --map skills/knuaf-doc/references/dairy/corrections/dairy-clear-map.json \
  --out <사본 xlsx> --receipt <영수증 json>
```

- `--project`는 필수다. 없으면 `output_context_required`(rc 2)로 거절한다.
- `--major dairy`도 필수다. 없으면 `major_id_required`(rc 2)다.
- `--source`는 필수다. 28시트 원본이 있어야 한다 — 번들 양식(17시트)은 대신하지
  못한다.
- 성공하면 stdout에 `{"status": "blank_template", "cleared": 1070,
  "formulaProtected": 0, "formulaCachesInvalidated": 22828, "missing": 0}`이
  나오고 rc 0이다.

## 출력 위치와 채우기 — 이 전공의 계약

- **출력 위치: 프로젝트 밖도 허용한다.** 학생이 저장 위치를 직접 고른다. 대신
  원본을 덮어쓰지 않는다 — 출력이 원본과 같은 경로면
  `ValueError("refusing to write over the source workbook")`, 이미 있는 파일이면
  `FileExistsError`로 **폴더를 만들기 전에** 거절한다.
- **값 채우기(`gg_excel_fill`)와 파이썬 재무 계산은 낙농에서 미지원이다.**
  입구에서 `fill_unsupported_for_major`로 거절하고 출력·영수증을 만들지 않는다
  (`FILL_CLOSED_MAJORS`에 `dairy` 포함). 이 전공은 빈 사본(`clear`)까지만 연다.
  `dairy_cattle_milk_cash`·`hanwoo_herd_cash`도 계속 `unsupported`다.
  17시트 전공의 채우기·계산 동작은 그대로다.
