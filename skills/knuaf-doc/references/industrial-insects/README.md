# 산업곤충전공 문서·근거 모듈 (모듈 0.2.0)

`industrial_insects` 전공 모듈은 공용 작성 계약(`gg_major_contract`)에 선언된 동급 전공이다. 이 묶음은 **읽기 전용 계획·검토**만 제공한다. 정본 기록은 기존 `gg.py apply` 트랜잭션만 바꾸고, 논문·XLSX·재무 출력은 공용 가드 B가 `unsupported_output`으로 거부한다.

| 기능 | 상태 | 진입점 |
|---|---|---|
| 질문 목록(프로젝트 요약 20개 + 제품 라인·계획 연도 반복 질문, 여섯 답변 상태) | 지원 | `gg.py major-plan <폴더>` |
| 제품 라인·연도별 질문 상태(인스턴스 출처) | 지원 | `gg.py insect-plan <폴더>` (선택 JSON 없이) |
| 선택형 문서 계획 + 선례 위치 연결 | 지원 | `gg.py insect-plan <폴더> --input <폴더 안 선택.json>` |
| 공식 통계 원자료 근거 검토(공용 6축) | 지원 | `gg.py insect-evidence <폴더> --pdf <R0> --xlsx <R1>` |
| 선례 PDF 식별 대조(해시·쪽수) | 지원 | `scripts/gg_insect_precedent_check.py --f0 … --e1 … --e2 … --e3 … --e4 …` |
| 원자료 영수증(선택 셀) | 지원 | `scripts/gg_insect_source_receipt.py --pdf <R0> --xlsx <R1>` |
| 논문 본문·DOCX/HWP, 곤충 XLSX, 재무 계산 | 미지원 | 공용 가드가 거부 |
| 곤충 벤치마크 팩 | `empty_slot` | 승격 조건 미충족(아래) |

모든 명령은 표준 출력으로 JSON만 내고 파일을 만들지 않는다. 오류는 경로·원문 없이 고정 사유 코드로만 나온다.

## 작성 선례 — 동급 예시

`precedents.json`은 원본 PDF 다섯 건의 **관측 지도**다. 원본은 비공개이며 ID와 SHA-256으로만 지칭한다.

- F0: 교수가 배포한 완성형 산업곤충 예시(70쪽). 공식 지침이나 빈 양식이 아니다.
- E1–E4: 심사를 통과한 선배 논문.
- 다섯 건 모두 `example_observed`이고 서열이 없다. 장·표의 존재는 관측 사실이지 강제 목차·표 수가 아니다. 예시의 사업 수치·학생 정보는 기본값이 아니다.
- 각 관측의 `verification` 값은 지도 안 `verification_codes`에 닫힌 목록으로 선언되고, 코드마다 근거 연결 가능 여부(`usable`)가 고정돼 있다. 텍스트층이 거의 없는 쪽(`content_unresolved`)은 렌더·OCR 확인 전까지 근거로 연결할 수 없다.
- 독립 대조 기록(2026-09-25): ① 작성자와 분리된 감사가 원본 다섯 건으로 기존 지도 140행(F0 목차·7개 장 시작 쪽·표 1–24와 연속 쪽, E1–E4 목차·표 위치)을 대조해 전부 일치를 확인했다. ② 빠져 있던 E2 3·29·30·60쪽, E3 7쪽을 미해결 쪽으로 추가해 145행이 됐고, 이 최종 지도(원본 제목·이름 포함)를 별도 검증자가 다시 원본과 대조해 전부 통과했다. 등록부의 계보 `verified`는 이 최종 지도 해시에만 묶인다. E1·E3의 미해결 쪽은 렌더상 표지·서명 양식·빈 쪽으로 보였으나 분류는 바꾸지 않았다(근거 연결 불가 유지).
- `gg_insect_precedent_check.py`의 `verified`는 **해시·쪽수 동일성**만 뜻한다. 표 내용·역할의 정확성은 위 독립 대조가 근거다.

### 선택 JSON

프로젝트 폴더 안의 JSON 목록. 빈 목록이면 `needs_selection`. 중복 키·모르는 키는 거부한다.

```json
[
  {
    "section_id": "preface",
    "action": "adapt",
    "reason": "대상 종과 사업 목적에 맞게 도입 순서를 조정",
    "observation_refs": [
      {"source_id": "F0", "physical_page": 7, "object_label": "page"}
    ]
  }
]
```

- `action`: `use` 또는 `adapt`. `adapt`는 `reason` 필수.
- 선례 위치의 관측 역할이 선택한 절과 다르면 `adapt` + `role_fit_reason`이 필요하고 결과는 `fit_needs_review`.
- `source_refs`는 정본에 등록된 source ID와 위치 문자열만 받는다(등록 ID 확인까지, 바이트 대조는 아님).

### 제품 라인

곤충 사업은 한 종에서 여러 제품(생충·건조품·분변토·처리 서비스)이 나온다. 모듈 0.2.0부터 제품 흐름마다 **라인**을 두고 라인별로 따로 묻는다.

- **선언:** `industrial_insects.line_inventory` 질문("팔거나 만들 제품 라인을 모두 알려 주세요")으로 시작한다. 도우미는 라인마다 id `l01`, `l02`…를 붙여 `gg.py apply`로 `industrial_insects.line.<id>.label` 사실과 `line_inventory`(id 목록)를 함께 등록한다. 한 번 쓴 id는 다시 쓰지 않는다.
- **폐기:** `line_inventory`에서 빼고 `industrial_insects.line_retired`에 넣는다. 폐기 라인의 기존 답은 지우지 않는다. 다음 id는 폐기 id까지 포함한 최대 번호 + 1이다.
- **라인 질문:** `industrial_insects.line.<id>.<field>` — 종·용도·제품 형태·역할(main/byproduct/processed/service)·판매 단위·회차 일수·연간 회차 수·첫해 판매 회차·입식량과 단위·종충 확보·생존율과 기준·회차당 외부 판매량·상자 수·단 수·상자당 밀도·먹이 종류·조달·판로·단가(원)·단가 근거·가공 투입량. 연말 사육 중 회차는 `industrial_insects.plan_years`에 있는 연도마다 `…line.<id>.year.<yyyy>.year_end_in_process`로 따로 묻는다.
- **상속 없음:** 기존 프로젝트 요약 질문(종·제품 형태·판매 가능 수량 등)의 답을 라인 답으로 옮기지 않는다. 기간·범위가 달라 같은 결정이 아니다. 학생이 "이전 답이 이 라인에도 해당한다"고 확인하면 새 라인 사실로 등록하고, 원사실은 `depends_on`으로 연결한다.
- **출력:** `insect-plan`은 라인·연도 인스턴스와 질문 상태만 보이고 학생 값은 보이지 않는다(검증된 라인 id만 예외). 합계·연 판매량 같은 계산은 하지 않는다.

### 모듈 0.2.0으로 옮기기

0.1.0으로 바인딩된 프로젝트는 공용 규칙상 보류된다(`binding_invalid`). 같은 `common.major_id` 사실을 `gg.py apply`로 **같은 id의 새 revision**(`module_version: "0.2.0"`)으로 갱신한다. 새 사실을 덧붙이면 `duplicate_major_facts`로 막힌다. 다른 답·질문 횟수는 그대로다. 바인딩이 새 revision이 되므로 **교수 승인은 다시 받아야 한다**. 내용 검토는 바인딩만으로 무효가 되지 않는다.

### 핵심 전제 목록

[premise-probes.md](premise-probes.md)는 공용 인터뷰 형식(핵심 전제 목록)을 따르는 곤충 전공 문서다. 라인 선언, 계획 연도, 먹이·배지 조달, 생존율과 기준, 상자 수·단 수·밀도, 연간 회차, 첫 판매 시점, 첫해 판매 회차, 연말 사육 중 회차, 종충 확보, 용도별 법 체계, 가공 요건, 효능 광고, 단가 근거, 단가 — 18개 전제를 질문 항목 하나씩에 연결한다. 라인 질문에 연결된 전제는 인스턴스 출처(`insect-plan`)를 적었다. 묻는 거리일 뿐 사실·기본값이 아니다.

### 질문 상태

`question_states`는 값 없이 상태만 보인다. 폐기(`superseded`)된 답은 빼고 공용 `gg_core.question` 판정을 쓴다. `reuse`는 "다시 묻지 않아도 됨"이지 검증·승인이 아니다. 답이 둘 이상이면 `multiple_active`, 분쟁 중이면 `disputed`로 표시한다. 현재 질문은 **프로젝트 수준 요약**이며 종·제품 라인별 완결성을 나타내지 않는다(여러 라인의 질문 구조는 공용 인터뷰 개편과 함께 다룬다).

R0 값 출처: 농림축산식품부, 「2024년 곤충산업 현황 실태조사 결과」(2025.09.01 게시, https://www.mafra.go.kr/bbs/home/789/574978/artclView.do), 공공누리 제1유형(출처표시). R1은 포털 이용허락범위가 공란이라 권리가 확인되지 않았으므로 이 문서에 셀 값을 싣지 않는다. 값은 사용자가 준 R1 원본에서 명령이 실행 중에 읽는다.

- R0 본문 1–3쪽의 일부 문장값(지역 순위, 전년 종사자 수, 전·겸업 수)은 같은 문서 4쪽 표와 맞지 않아 채택하지 않는다.
- 판매액 총계는 **산업 맥락 관측값**이다. kg당 가격·농가 생산성·학생 매출 입력으로 바꾸지 않는다.

근거 축(공용): 취득 `bytes_held`, 관측 `exploratory`(PDF 시각 대조는 명령이 수행하지 않음), 권리 `unconfirmed`(R1 포털 이용허락범위 공란, R0 재배포 미심사), 충돌은 위 비교 결과, 적용 가능성은 동애등에만 `unverified`, 승인 `unapproved`. 모든 행이 승인 후보가 아니다.

## 내장 참조자료 재사용 등록

같은 원본을 다른 사용자가 폴더나 첨부로 줘도 다시 파싱하지 않도록 공용 재사용 등록부(`references/builtin-sources.json`)에 9건을 올린다. 등록부는 **판정만** 한다. 원본을 다시 읽지 않는 것은 이 안내를 따르는 작업 규칙이며 코드가 막지 않는다. 대상은 F0·E1–E4 PDF의 위치 지도뿐이다.

| 등록 ID | 원본 | 역할 | 기대 판정(`source-resolve`) | 할 일 |
|---|---|---|---|---|
| `insect.example.f0`, `insect.example.e1`–`e4` | F0·E1–E4 PDF | `narrative_exemplar`, 산출물 `precedents.json` | 자기 키로 `reuse_ready` | 원본을 다시 파싱하지 말고 `precedents.json`과 `insect-plan`을 쓴다 |
| `insect.example.e3-hwp`, `e4-hwp` | E3·E4 HWP | 식별값만 | `needs_excerpt` | HWP↔PDF 동일성은 확인되지 않았다. 필요하면 해당 PDF를 쓴다 |
| `insect.stat.r0`, `insect.stat.r1` | R0 PDF·R1 XLSX | `reference_only`(식별값만) | 모든 용도 `blocked/role_mismatch`(정상) | 내장 추출물이 없다. `insect-evidence`가 고정 해시 확인 후 선택 셀만 읽는다 |

- 원본마다 키가 따로 있고 서로 상속하지 않는다. 키: `insect-precedents:f0-locator-map`, `…:e1-locator-map` … `…:e4-locator-map`.
- 요청 예: `--requested-use '{"kind":"narrative_reference","keys":[{"kind":"delimited","value":"insect-precedents:f0-locator-map"}]}'`. 키 카탈로그(`--key-catalog`)에 같은 키가 `verified`로 있어야 한다. 카탈로그 파일은 저장소에 두지 않는다.
- 학생 예시는 제목·이름만 식별값으로 둔다(`precedents.json` 원본 항목의 `title`·`author`). 학번·파일명·주소·서명은 넣지 않는다. 원본에 제목 쪽이 없으면 `title: null`이다.
- `precedents.json`이 바뀌면 등록부의 산출물 해시가 맞지 않아 판정이 `blocked`가 된다. 다시 독립 검증한 뒤 해시를 고친다. 등록부 문서가 바뀌면 그 전에 만든 `source-register` 선택 JSON은 무효(`not_committed`)가 된다.
- 재사용 판정에는 전공 구분이 없다(공용 한계). 곤충 프로젝트가 아닌 곳에서 이 선례를 근거로 쓰지 않는다.

## 팩 승격 조건 (이번 묶음 미충족)

원본 해시·파서/출력 해시·쪽/셀 위치·단위·모집단 영수증, PDF 시각 대조, 권리 확인, 충돌 해소를 모두 갖춘 행만 곤충 팩으로 승격한다. 현재는 `empty_slot`이다.

## 한계

- 종별 사육 조건·수율·가격, 곤충 재무 산식은 추가 원자료와 별도 검증이 필요하다.
- 법적 요건은 종·용도·실제 판매 행위별 현행 조문으로 따로 확인한다.
- 실제 본문·DOCX/XLSX/HWP, 재계산, 내용 검토, 교수 확인은 각각 별도 검증이다.
