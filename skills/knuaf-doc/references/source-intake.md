# 자료 투입과 조사 투명성

공통 출처 ID·해시·물리 페이지·절/표 작업 기록은 [source-contract.md](source-contract.md)가 정본이다. 이 문서는 자료를 언제 읽고 어떤 발췌·조사 기록을 남길지에 집중한다.

**식별 전용 우선순위:** [source-identities.json](source-identities.json)에 등재된 출처에 한해 스킬·등록부·저장소에는 해시와 서지 식별정보만 남긴다. 발췌·인용문·웹 본문 스냅샷을 만들지 않으며, 이 규칙이 아래 §1-1의 발췌 의무와 §2의 웹 스냅샷 지시보다 우선한다. 발췌본이 없는 상태를 보완할 누락으로 취급하지 않는다. 카탈로그 등재는 재사용 권한이나 검증·승인을 부여하지 않는다. 신규 등록에 적용하며 기존 등록 자료의 연결된 발췌본에는 소급 적용하지 않는다.

## 1. 자료 투입 시점

자료 등록 전 [intake-selection.md](intake-selection.md)의 Q1a/Q1b/Q1c를 따른다. 현재 작성물 지정과 참고자료 폴더 제공을 구분한다. 아래의 직접 열람은 지정된 후보의 확인 또는 확인된 자료 처리이며, 폴더에서 찾은 초안을 현재 원고로 자동 채택하는 지시가 아니다.


파일 성격에 따라 필요한 시점이 다르다. 전부 초기에 받으면 쓰지도 않을 자료로
컨텍스트를 낭비하고, 전부 나중에 받으면 이미 쓴 원고를 뒤집는다.

| 구분 | 시점 | 방식 |
|---|---|---|
| 작성 중이던 본문·재무 엑셀 | 초기 필수 | 경로 확인 후 직접 열어 검증 |
| 학교 작성요령·선배 논문 | 초기 필수 | 경로 확인 (목차·문체 추출원) |
| 농업 자료·매뉴얼·시세 | 폴더 등록 | 등록 뷰만 발행하고 필요할 때 선택 열람 |
| 웹 링크 | 수시 | 즉시 스냅샷 저장 후 출처 등록 |
| 교수 피드백·추가 자료 | 수시 | 즉시 등록 + 영향 절 판정 |

### 초기 필수인 이유
- 기존 원고의 현재성 확인과 이어쓰기 선택은 [intake-selection.md](intake-selection.md)를 따른다. 원고가 없으면 그 답을 보존하고 신규 작성으로 진행한다.
- 작성요령을 모르면 목차 뼈대를 세울 수 없다. 나중에 알면 전 장을 재편해야 한다.

### 폴더 등록 방식
참고자료는 파일별 첨부를 요구하지 않고 폴더 경로를 받는다. 현재 원고·재무 파일은 별도로 파일명/위치 또는 첨부를 받아 선택을 확인한다.

스캔은 증거만 만들고, 등록은 사용자가 명시적으로 고른 자료에 대해 별도로 일어난다. `03_sources.md`는 실패 경로를 포함한 어떤 경로에서도 덮어쓰거나 다시 만들지 않는다. 출처 인덱스는 등록이 끝난 뒤에만 생성 뷰로 발행된다.

1. `scripts/gg.py source-scan <작업폴더> --root <자료폴더> --registry <경로> --key-catalog <경로> --policy <경로>` — 폴더를 스캔해 봉인 수령증 `sources/intake/<scan_id>.json`(결정적 바이트)과 재생성 가능한 진단 `sources/intake/<scan_id>.diagnostics.json`을 남긴다. 스캔만으로는 아무것도 등록되지 않는다.
2. `source-resolve <작업폴더> --source-hash <sha256> --requested-use <json> --registry <경로> --key-catalog <경로>` — 읽기 전용으로 각 자료가 요청 용도에 쓸 수 있는지 판정한다. 통계 용도면 `--catalog`·`--packs-dir`을 함께 준다.
3. `source-register <작업폴더> --selection <json> --expected-revision <N> --request-id <id> --registry <경로> --key-catalog <경로>` — 사용자가 명시적으로 고른 자료만 등록한다. 선택은 스캔된 파일별 `relative_id`·`content_sha256`과 `byte_source`를 묶고(`scanned_external`이면 `--external-root` 필수), 커밋되면 생성 뷰가 `sources/generated/<view_id>/source-index.json`에 발행된다. 폴더 통째 등록은 없다.
4. `source-view <작업폴더> --request-id <id>` — 발행된 뷰를 연다. 각 절 작업에 들어갈 때 이 뷰에서 관련 자료만 골라 읽는다.
5. **읽었으면 반드시 발췌본을 남긴다** (아래 1-1항). 읽고 넘어가지 않는다.
6. 뷰에 있으나 어느 절에도 쓰이지 않은 자료는 lint WARN으로 보고한다.

## 1-1. 읽은 자료는 반드시 발췌본으로 남긴다

원본을 한 번 읽고 지나가면 그 내용은 **대화 컨텍스트에만 존재한다.**
세션이 압축되거나 다른 모델로 넘어가면 사라지고, 원본을 다시 파싱해야 한다.
HWP·PDF 파싱은 비용이 크고 표가 깨지므로 같은 결과가 나온다는 보장도 없다.

**원칙: 원본을 연 순간, 그 자리에서 발췌본을 만든다.**

### 저장 위치

    <작업폴더>/sources/
      web/          웹 링크 스냅샷 (2항)
      extracts/     사용자 첨부 파일 발췌본  ★
        <원본파일명>.md

### 발췌본에 넣을 것

    ---
    원본: <original-path>/선배논문_김OO.hwp
    형식: hwp | 추출: (사용한 파싱 수단) | 추출일: 2026-09-03
    등급: 2 | 역할: 문체·분량 참조 (규칙 근거 아님)
    추출범위: 전문 | 한계: 표 셀 일부 축약됨
    ---

    ## 구조
    (목차·시트 구성·장별 분량 등 뼈대)

    ## 이 논문에 쓸 것
    (해당 절과 연결지어 정리. 인용할 수치는 원문 표현 그대로)

    ## 원문 인용
    (그대로 보존해야 할 문장·수치·표. 요약하지 말 것)

### 요약만 남기지 않는다

요약은 이미 판단이 섞인 결과다. 나중에 다른 절에서 필요한 정보가
요약 단계에서 버려졌을 수 있다.
**수치·표·규정 문구는 원문 그대로 옮긴다.** 판단은 별도 항목에 적는다.

### 중복 파싱 방지와 시각 검증 예외

`sources/extracts/`에 같은 revision·범위의 발췌본이 있으면 텍스트 파싱을 반복하지 않는다. 다음 경우에는 원본을 다시 열 수 있다.

- 원본의 표·병합·각주·쪽 배치를 시각적으로 검증해야 할 때
- 원본 SHA-256, 물리 페이지, 추출 방법이 바뀌었을 때
- 기존 발췌본의 범위·한계로 해당 주장을 판정할 수 없을 때

재검토는 새 revision과 범위를 `source-contract.md` 계약 및 작업 기록에 남긴다. 기존 발췌본을 덮어쓰지 말고 보완 발췌본으로 추가한다.

공통 XLSX(X01·X02)도 같은 규칙이다. 투입된 파일의 SHA-256이 참조집합 멤버와 정확히 같으면 다시 파싱하지 않고 `source-resolve`로 등록 추출본(`kang-finance-workbook.json`, `template_structure`)을 쓴다. 해시가 다르면(다시 저장되거나 학생이 채운 사본) 17개 시트 이름이 모두 같아도 새 파일로 보고 새로 파싱한다. `layout_family`은 입력 지도 좌표 힌트일 뿐 파일 식별이나 재사용 승인이 아니다.

전공 전용 통합문서는 공통 양식보다 우선한다. `known_workbooks`의 `base_for_major` 항목(예: 원예환경시스템전공 H01)이 해당 전공 폴더에서 유효하게 확인되면 정본 선택이 없어도 그 파일이 기본이 되고, 사용자가 다른 파일을 명시 선택하면 그 선택이 이긴다.

### 중간 투입 처리
작업 도중 자료를 받으면 즉시 (1) 자료 등록 — 위의 source-scan→source-register 흐름을 새 요청으로 진행 (2) 어느 절에 영향을 주는지 판정
(3) 이미 작성된 절에 영향을 주면 사용자에게 재검토 필요를 보고
(4) 재무 입력을 바꾸면 workflow-order.md의 재검산 게이트를 다시 돈다.

### 본문 설명에 쓸 도표와 데이터

절의 논점을 설명하는 원문 도표나 통계가 있으면 텍스트 요약만 남기지 않고 실제 페이지·표/그림 번호, 해석에 필요한 축·단위·범례·주석, 적용 가능한 범위와 이용 조건을 발췌 기록에 연결한다. 원문 도표 재사용과 원자료 재도식화의 선택·제작·본문 삽입은 [narrative-expansion.md](narrative-expansion.md)의 단계 E를 따른다. 자료 검색·목록 작성만으로 필요한 시각자료의 완성을 대신하지 않는다.

## 2. 웹 링크 처리

링크는 파일과 달리 내용이 바뀌거나 사라진다. 받는 즉시 고정한다.

1. 스냅샷 저장: 본문을 추출해 sources/web/ 아래 날짜_슬러그.md 로 저장한다.
2. 출처 등급 판정(3항)
3. 증거 원장 등록: locator에 URL, method에 취득 경로를 적는다.

스냅샷 머리말 항목: url / accessed(접속시각) / title / grade / method
링크가 죽어도 스냅샷이 근거로 남는다.

## 3. 출처 허용 및 금지 기준

> ℹ️ **적용 범위**: 본 출처 허용 및 비공식 자료 금지 기준은 **모든 전공 공통 기본값**이다([사용자 결정 2026-10-06 22:39]). 공공 통계·학술·정규교재·본인 직접 조사 외 언론·블로그·인터뷰 등 비공식 카더라 출처는 전 전공에서 인용이 금지된다.

학부 졸업논문(영농창업계획서)의 공신력과 객관성을 담보하기 위해 출처는 **공식 통계·공공자료·학술·연구기관·학교 자료·교재·작성자 직접 조사**로 엄격히 한정한다. 언론 기사, 블로그, 타인 인터뷰 등 비공식 카더라 자료는 본문에 일체 인용할 수 없다.

### 허용 출처 vs 금지 출처

| 구분 | 허용 범위 | 상세 유형 및 규격 |
|---|---|---|
| **허용 (공식·학술)** | **1. 정부·공공기관 공식 통계 및 공공 DB** | 통계청(KOSIS), 농촌진흥청(농사로, 흙토람, NCPMS), 농림축산식품부, 산림청, aT(KAMIS, KATI), 기상청 등 |
| | **2. 법령 및 공공 정책 공고** | 국가법령정보센터, 지자체 조례·고시, 공공기관 사업 지침 |
| | **3. 학술논문 및 연구기관 보고서** | DOI 확인 학술논문, 학회지, 국·공립 연구기관 보고서(원예특작과학원, 도 농업기술원 등) |
| | **4. 학교 공식 자료 및 정규 교재** | 한국농수산대학교 수업·강의자료, 공식 창업논문 작성요령, 김성학 교재 등 정규 농업 교재 |
| | **5. 작성자 직접 조사** | 학생 본인의 현장 실습 일지, 직접 견학·상담 기록, 본인 촬영 사진 (반드시 '작성자 직접 조사'로 명시) |
| **금지 (비공식 자료)** | **언론 보도 및 기사** | 중앙지, 지방지, 농업전문지(농민신문 등), 방송, 인터넷 뉴스, 기사형 인터뷰 전면 금지 |
| | **블로그·카페·커뮤니티** | 네이버/다음 블로그, 농업 카페, 온라인 커뮤니티 글 일체 금지 |
| | **타인 인터뷰 및 사례담** | 비공식 농가 인터뷰 기사, 타인 경험담, 카더라성 구두 진술 전면 금지 |
| | **개인 SNS 및 영상** | 유튜브, 페이스북, 인스타그램 등 개인 소셜미디어 금지 |
| | **쇼핑몰 상품 페이지·후기** | 스마트스토어, 온라인 쇼핑몰 판매 페이지, 구매 후기 금지 |

### 비공식 출처 금지 원칙 (예외 없음)

1. **보조 인용 금지**: 상위 공식 자료가 있더라도 언론 기사나 농가 블로그를 '보조 사례'로 덧붙이는 행위를 금지한다.
2. **시범값 예외 폐지**: 공식 통계가 없는 신규 품목이라도 쇼핑몰·블로그 복수 교차를 이유로 시범값을 만들어 본문에 넣을 수 없다. 공식 통계가 없으면 상위 품목 통계를 인용하거나 "확인 불가"로 명시하고 임의 추정하지 않는다.
3. **업체 게시 판매가 인용 금지**: 쇼핑몰이나 업체 홈페이지(봉산허브, 허브아이 등)의 게시 판매가는 공식 도매가·농가수취가가 아니므로 **참고 불가 (출처 불가)**로 처리한다.
4. **미확인 값의 처리**: 공식 자료에서 확인하지 못한 값은 임의로 추정하거나 유추하지 않고 반드시 **"확인 불가"**로 남겨두고 해당 계산·주장만 보류한다.

### 출처 등록 및 게이트 검사

기계 게이트는 등록 레코드의 `kind`가 금지 목록(`news, blog, interview, sns, cafe, shop, press`)과 일치하거나 `grade`가 3·4일 때 오류를 보고한다. 단 `kind: interview`인 학생 본인의 직접 조사·견학·상담은 `source_type: author_survey` 또는 정확한 `source: 작성자 직접 조사` 표시가 있을 때 종류 금지에서 제외한다. 3·4등급 거부는 이 경우에도 유지한다. `verified: user-stated`나 "사용자 견학"이라는 설명만으로 이 예외가 적용되지는 않는다.

**신규 인용 출처는 사용 전에 유형 분류가 필수다.** 본문·표·재무 주장에 쓰기 전에 원문을 확인해 `kind`와 적용 등급, 출처 역할·locator를 등록하고 허용 여부를 검토 기록에 남긴다. 기존 미분류 출처도 인용 전에 같은 검토를 거친다. 학생 원답변이나 미분류 원자료를 저장·보존하는 것은 인용 승인이 아니다. 분류 필드가 없는 기록, `kind: file` 같은 일반 파일 기록, 인라인 출처 문구만으로는 기사인지 기계가 판별하지 못한다. 미분류 신규 등록을 코드가 차단하는 기능은 없으며, 이 필수 분류는 작성·검토 계약이다.

본인 조사 원문은 `verified: user-stated` 상태로 보존하고 조사일·대상·원답변 위치를 남긴다. 기존 `kind: interview` 기록은 직접 경험 여부를 확인한 뒤 같은 출처 ID의 `source_type` 또는 `source` 표시만 정정하고 개정·사유를 기록한다. 이 표시는 외부 사실의 공식 검증이나 재무 입력값의 승인으로 승격하지 않는다.

- **허용 등록 예시 (공식 통계)**:
  ```json
  {"id":"R-011","kind":"stat","claim":"[기준연도] [지역] [작목] 재배면적 [공식 통계에서 확인한 면적] ha",
   "source":"KOSIS 국가통계포털","source_type":"official_stat",
   "year":"[기준연도]","locator":"[확인한 공식 통계표·행·열]"}
  ```
- **허용 등록 예시 (작성자 직접 조사)**:
  ```json
  {"id":"R-012","kind":"interview","claim":"[학생 예정지]에서 [확인한 토성] 확인",
   "source":"작성자 직접 조사","source_type":"author_survey",
   "verified":"user-stated","year":"[조사연도]","note":"[직접 조사일·대상·원답변 위치]"}
  ```
- **차단 대상**:
  언론 기사, 농가 블로그, 타인 기사형 인터뷰는 인용 금지다. 등록 레코드의 금지 `kind`/`grade`를 `gg_core.checks`가 검사하지만, 유형 필드가 없거나 잘못 분류된 기록의 실제 내용을 자동 분류하지 않는다. 위 자리표시자는 실제 근거로 채우기 전 인용할 수 없다.

## 4. 조사 로그 (04_research_log.md)

사용자가 '어디까지 찾아봤는지, 이상한 자료를 가져온 건 아닌지' 확인할 수 있어야 한다.
결과만 적지 말고 과정을 적는다.

### 필수 기록 항목
1. 질문 요지 — 무엇을 물었나
2. 경로 — 자체검색 / 웹조사 / 브라우저 / 문서파싱 / 하위모델 위임 / 사용자제공
3. 확인한 출처 전체 — 채택한 것과 버린 것을 모두 적는다
4. 채택 결론과 근거
5. 배제 사유 — 왜 버렸는지
6. 한계 — 이 조사로 확인되지 않은 것

### 왜 배제 사유가 중요한가
채택한 것만 보여주면 유리한 것만 골랐는지 알 수 없다.
버린 것과 이유를 함께 남겨야 조사가 검증 가능해진다.

### 기록 서식
각 조사에 Q-nnn 번호를 붙이고 아래 순서로 적는다.
제목줄, 일시, 경로, 질문요지, 확인한 출처 표(출처·등급·내용·채택여부),
채택 결론, 배제 사유, 한계.
출처 표의 채택 열에는 O(채택) / X(배제) / 보류를 적는다.

## 5. 하위 모델 조사 결과 취급

위임 조사는 효율적이지만 결과를 그대로 신뢰하지 않는다.
실제 발생한 오류 유형(2026-09-02):

| 유형 | 사례 | 방어 |
|---|---|---|
| 소매가와 농가가 혼동 | 쇼핑몰 소매가를 농가 수취가로 제시 | 유통단계를 명시적으로 질문 |
| 비용 누락 | 표고 계산에서 인건비·수선비 0원 처리 | 직접 재검산 |
| 이중계산 | 재식밀도와 회전수를 곱해 실현 불가 물량 | 실측 사례로 역산 대조 |
| 자기모순 | 한 답변에 6배 차이 수치 공존 | 답변 내 일관성 검사 |

### 위임 프롬프트에 반드시 넣을 것

가격 조사에는 [price-research-routes.md](price-research-routes.md)의 품목·상품·거래 단계별 경로와 작업 계약을 함께 전달한다. 출처 목록은 조사 출발점이며 가격 증거가 아니다. 조회 결과·조회 조건·기준일을 실제 확인한 뒤 등록한다. 접근 오류, 품목 미등재, 선택 기간 거래 결과 없음, 조건 불일치, 공개 단가 미확인을 구분한다. 동일 검색을 반복하지 말고 조사한 범위와 다음 적합 경로를 기록한다. 부족한 가격은 해당 계산만 보류하며 무관한 논문 작성을 멈추지 않는다.

- 과거 발생한 오류 유형 명시('이런 실수가 있었으니 피하라')
- '제시한 수치가 현실적인지 스스로 검산하라'
- '확인 못 하면 확인 불가라고 하라. 지어내지 마라'
- 출처를 기관·자료명·연도·URL까지 요구

### 받은 뒤
- 수치는 직접 재계산해 대조
- 논문·법령은 별도 호출로 실재 검증
- 원장 verified는 검증을 실제 수행한 뒤에만 승격
