# 본문 작성 사양서 (절 작성용)

출처·성격: S0 보존 스냅숏의 내부 작성 명세를 현행 `../thesis-level.md`·`../source-contract.md`·`../figure-photo-policy.md`에 맞춰 정리했다. 학교 작성요령의 직접 발췌가 아니며 선배 관찰은 학교 의무가 아니다. 현행 특용작물 수준 기준을 따르고 특정 사례의 글자수·표그림 개수를 목표로 삼지 않는다.

성격: 이 스킬의 내부 작성 명세다. 학교 원문 규정이 아니며, 학교 원문·교수 지시와 충돌하면 그쪽을 따른다.

절별 출처·규칙·수치 묶음은 [source-contract.md](../source-contract.md)와 [section-ledger.md](../section-ledger.md)의 작업 기록으로 제공한다. 이 문서는 문장 작성 판단을 정하며, 프롬프트에만 넣은 요구를 프로젝트 정본으로 간주하지 않는다.

절 작성에는 현재 정본의 해당 절 묶음, 적용 학교 원문, 아래 품질 기준을 함께 사용한다. 짧은 위임 프롬프트는 이 자료의 위치를 안내하며 자료 자체를 대신하지 않는다.

## 0. 받는 것

`gg.py bundle`과 [section-ledger.md](../section-ledger.md)에 따라 다음의 현재 개정 자료를 실제로 읽는다. 빠진 자료는 해당 판단만 보류하고 가능한 초안을 계속한다.

1. 쓸 절 ID와 현재 DRAFT, 보존된 원답변
2. 적용 학교 원문 위치 및 규칙 (로컬 CH 파일은 보조 대조)
3. 사실·목표·가정·계산의 구분과 값·단위·기간·출처 ID/개정/위치
4. 조사 원문과 학생 계획에 적용할 수 있는 범위
5. 선택된 문체와 [exemplar-quality.md](../exemplar-quality.md)의 해당 장 기준

정본 밖 파일이나 프롬프트에 붙인 값만으로 정본(project.json)을 대체하지 않는다. 정본과 충돌하면 원답변·근거 위치를 확인해 변경을 기록한다.

## 1. 표기 규칙 (모든 절 공통)

**규범: `F_format.md`** — 학명·인용·단위·표그림·번호체계는 그 파일을 따른다.
이 문서에 규칙을 복제하지 않는다.

위임 시 적용 학교 원문과 보조 `F_format.md`의 경로를 전달하고 실제 읽기를 확인한다. 해당 파일이 없으면 학교 원문에서 확인하며 서식을 추정하지 않는다.

## 2. 서술 원칙

### 인칭과 화법
화자 선택은 [narrative-expansion.md](../narrative-expansion.md)의 학생 화자 계약을 따른다. 이 명세나 아래 예문이 별도 화자 정책을 만들지 않는다.

    1인칭 예: 이 지역의 여름 기온을 고려해 냉방 설비를 도입하기로 하였습니다.
    보고서체 예: 이 지역의 여름 기온을 고려해 냉방 설비 도입을 검토한다.

### 자료를 나열하지 말고 판단으로 연결
모든 수치와 자료는 "그래서 내 농장에 무엇을 의미하는가"로 이어져야 한다.

    예시 구조: [확인한 시장 접근성] → [학생 작목의 운송·신선도 조건] → [확정한 판로 계획].
    구체 지역·인구·소요시간은 현재 공식 근거와 학생 계획으로만 채운다.

### 불리한 사실을 숨기지 않는다
적자·위험·한계를 정면으로 다루되, 대응책과 함께 쓴다.
이것이 신뢰를 만든다. 낙관만 쓰면 심사에서 먼저 지적당한다.

### 근거와 의미가 연결된 수치
현재 사실·계산 또는 승인된 검토용 가정의 수치만 사용하고 종류를 구분한다.
계산이 필요하면 산식을 명시한다. 필요한 값이 없으면 해당 판단을 보류하되
다른 입력으로 설명할 수 있는 본문은 계속 작성한다.

## 3. 작문과 윤문 연결

학생 화자·내용 확장·불확실성의 위치와 설명 충분성은
[narrative-expansion.md](../narrative-expansion.md)를 따른다.
완성된 확장 초안의 의미를 보존하는 윤문과 전후 대조는
[korean-polishing.md](../korean-polishing.md)가 소유한다.
문장 수·변경률·장마다 예외 몇 개 같은 상한으로 내용 충분성을 판정하지 않는다.

학과 전문용어는 뜻을 흐리는 일상어로 치환하지 않는다.
쉬운 표현을 사용하되 근거·자기 농장 적용·실행 조건·한계가 빠지지 않았는지
[exemplar-quality.md](../exemplar-quality.md)의 해당 장 기준으로 확인한다.

## 4. 절 작성 절차

    1) 받은 규칙 파일에서 그 절의 요구 항목을 확인한다
    2) 요구 항목을 빠짐없이 배치한다 (하위 항목 포함)
    3) 사실·계산·승인된 검토용 가정을 구분해 해당 위치에 넣는다
    4) 각 수치·주장에 근거를 붙인다
    5) "그래서 어떻게 하겠다"로 마무리한다
    6) 표기 규칙을 다시 확인한다

## 5. 완료 전 자가 점검

    [ ] 요구 항목을 전부 다뤘는가 (규칙 파일과 대조)
    [ ] 선택한 인칭·종결어미로 일관되게 썼는가
    [ ] 받은 수치만 썼는가 (새 숫자를 만들지 않았는가)
    [ ] 학명 첫 등장에 전체 표기했는가
    [ ] 저자 3인 이상에 '등'을 붙였는가
    [ ] 수치와 단위 사이를 띄웠는가
    [ ] 최종 렌더에 Markdown 제어 기호가 노출되지 않는가 (절 DRAFT의 구조 표시는 허용)
    [ ] 자료 나열로 끝난 문단이 없는가
    [ ] 근거·자기 농장 적용·실행 조건·한계를 빠짐없이 설명했는가

## 6. 보고 형식

작성을 마치면 아래를 함께 보고한다.

    - 작성 분량 (공백 포함 글자수)
    - 다룬 요구 항목 목록
    - 사용한 수치와 그 출처
    - 필요했으나 받지 못한 수치 (있으면)
    - 판단이 필요했던 지점 (있으면)

수치가 부족해 추정한 부분이 있으면 **반드시 밝힌다.**
조용히 채워 넣는 것이 가장 위험하다.
