# 과수 S01 본문 집필 순서표

작성요령의 형식 규칙이 선배 견본보다 우선한다. 아래는 집필 질문·근거·재무 부록 역할의 연결이며 자동 본문 생성이나 재무 계산 규칙이 아니다. 시트 열은 계약의 15개 **역할명**이다. 실제 엑셀 시트명·주소·연도는 해당 학생 기준 엑셀에서 확인하며 역할명을 시트명으로 추정하지 않는다. 선배의 숫자·이름·서명을 복사하지 않는다.

## 집필·조립·렌더 확인

1. 학생 답변과 근거를 먼저 정리하고 Ⅰ → Ⅱ-1~5 → Ⅲ-1~7 → Ⅳ → 참고문헌·후미 → 요약 순으로 쓴다. 재무 절과 요약의 금액은 기준 엑셀 확인 전 `[확인 필요 — 엑셀 작성 후]`로 둔다. 계산 불가를 0이나 임의 추정치로 채우지 않는다.
2. 앞부분은 `gg_frontmatter`의 과수 프로필로 작성한다. 겉표지 한 쪽 다음에 표제면·제출서·인준서를 한 쪽에 묶고 목차로 이어진다. 이름·교수·위원은 확인된 값만 쓰며 미확인은 자리표시로 둔다.
3. 요약·학부모 동의서·감사의 글은 과수 앞머리 자동 마커에 포함되지 않으므로 원고에 직접 넣는다. 요약 제목과 산문은 목차 마커 뒤·Ⅰ 머리말 앞에 둔다. 장·후미·부록 역할은 `#`, Ⅱ·Ⅲ의 절은 `##`로 쓴다. 동의서 표기는 계약과 일치하는 `학부모 동의서`로 통일한다.
4. 목차를 손으로 입력하지 않는다. 표/그림은 실제 객체와 `표 N. …`/`그림 N. …` 캡션을 함께 넣는다. 캡션만으로 목차가 생겨도 실제 도면 확인을 대신하지 않는다. 표의 pipe 행 사이는 빈 줄 없이 연속 작성한다.
5. 기존 `build_docx.py <프로젝트> --in 본문.md --out build/검토전_논문.docx --major fruit_trees`로 조립한다. 프로젝트의 전공 바인딩과 명시 전공이 모두 일치해야 한다. manifest의 `major_id`·순서·physical_forms를 확인한다.
6. `gg_office.py word`는 Word를 화면 앞으로 띄운다. 다른 화면 작업과 조율하고 명시 허락 후 실행한다. 갱신 DOCX·PDF·세션 종료 증거를 보존한다. 기존 문서나 권한창·대화상자가 있으면 임의로 닫거나 복구하지 않고 중단한다.
7. `gg_toc_check.py`는 고정/미갱신 목차 숫자만 검사한다. 실제 쪽수 정확성은 PDF와 대조한다. 앞부분 로마숫자·본문 아라비아숫자, 표제/제출/인준 묶음, Ⅰ~Ⅳ와 후미 순서, 도표·잘림·빈 쪽을 쪽 이미지에서 확인한다. 목차는 분량에 따라 여러 쪽이 될 수 있다.

검토 전 DOCX는 제출 승인본이 아니다. `source_order_common_defaults`는 순서 기반 공용 배치이며 학교 원본의 글자 크기·간격·여백까지 재현했다는 뜻이 아니다. 원본과 실제 렌더의 차이는 별도 형식 검토에 남긴다. 공통 렌더러 변경이 필요하면 과수 안내에서 우회 구현하지 않고 공통 담당자에게 보고한다.
