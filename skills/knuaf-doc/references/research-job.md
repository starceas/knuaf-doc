# 조사 담당 계약 (research-job)

이 문서는 자료 조사(자료 수집·검색)를 맡은 **조사 담당(에이전트 모델)**이 읽고 기계적으로 따르는 순서 고정 절차서다.
호스트가 작업 분담(배치)을 켰든 앱 밖에서 선택적 위임을 받았든, 어떤 모델(Haiku·Terra·Sonnet·Astra 등)이 맡아도 동일한 순서로 찾고 동일한 서식으로 반환한다.

## 1. 주문서 수령 및 입력 계약

조사 담당은 메인이 전달한 작업 주문서를 받아 시작한다. 앱이 분담을 켠 경우 `jobs/<id>.json` 파일이며, 앱 밖 선택적 위임에서는 메인이 같은 칸을 손으로 채운 작업 계약을 전달받는다.

### 필수 기재 항목 (기계 필수 칸)
주문서에는 아래 필수 칸이 모두 채워져 있어야 한다. 하나라도 비어 있으면 담당은 작업을 시작하지 못하며(앱이 분담을 켠 경우 `gg.py delegate`가 주문서 생성을 거절), 임의로 채우지 않고 즉시 거절 사유를 알린다.

| 항목 | 설명 | 비고 |
|---|---|---|
| `research_type` | 조사 유형 (도매·소매·농가 수취가·생산량/재배면적·소득/경영비·물가상승률·노무비·학술문헌·법령 등) | [research-sources.md](research-sources.md) §1 판정 기준 |
| `questions` | 질문 목록 (질문 ID, 목표 지표, 채택 조건) | 아래 질문 단위 쪼개기 기준 |
| `routes` | 열어야 할 공식 경로 목록 (`{doc, id_or_name, url}` 형태) | 고유 ID 또는 문서명+출처명+URL |
| `keywords` / 별칭 | 검색어 및 별칭 목록 (정식명, 한약재명, 학명, 통계 상위 품목명) | [research-sources.md](research-sources.md) §4 별칭 목록 |
| `output_file` | 결과 파일 경로 (작업 칸 `out/` 아래 상대 경로) | 자기 출력 칸 내부 파일 |

- **질문 단위 분할 (질문 단위로 쪼갠다)**:
  - 주문서는 조사할 내용을 질문 ID(`Q1`, `Q2`…) 단위로 나눈다.
  - 질문마다 **목표 지표**(예: `<연도> <지역> <작목> 생산량, <단위>`)와 **채택 조건**(필수 조건: 상품 형태, 단위, 관측 지역, 기준연도 W/S 등)을 명시한다.
  - **조건 미확정 시 처리**: 필수 조건이 `미확정`으로 적힌 질문은 **후보 찾기**로만 수행한다. 결과는 확정값이 아니라 후보 목록으로 반환하며, 메인이 학생에게 조건을 확인한 뒤 확정한다.
- **경로 지정 형식**:
  - 행 ID·통계표 ID가 있는 문서: [dairy/research-routes.md](dairy/research-routes.md)의 `D01`·`H01`, KOSIS `DT_1J22003` 등 해당 식별자를 적는다.
  - 고유 ID가 없는 문서: [research-sources.md](research-sources.md) §2·§3, [price-research-routes.md](price-research-routes.md) 등 해당 문서명 + 표의 공식 출처명·URL을 적는다.
- **조건 명시**: 전공·품목·지역·기준연도(W/S)·상품 형태·단위는 구체적 값이거나 `미확정`/`해당 없음`으로 명시되어야 하며, 담당이 임의로 추정해 채우지 않는다.
- **소득·경영비 사전 확인 및 적용 예외**: 조사 유형이 소득·경영비인 경우 [research-sources.md](research-sources.md) §2의 조건을 그대로 따른다:
  - 전공이 지원 범위([majors.md](majors.md))에 있고 작목·지역이 확인된 경우에만 메인이 `gg.py rda-candidates` 실행 결과를 선행 확인해 첨부한다.
  - 지원 전공 밖이거나 미승인 상태이면 그 상태(`지원 밖`/`미승인`)를 적고 공식 외부 자료 조사로 이어간다.
  - 낙농(젖소·한우) 전공은 작물 소득·경영비 경로를 오적용하지 않고 축산 전용 경로([dairy/research-routes.md](dairy/research-routes.md))를 따르며, 이때 주문서 칸 값은 `해당 없음(축산 경로)`으로 적는다.
- **기조사 내역**: 이미 열어본 경로와 실패 이유가 기재되어 있으면 이를 확인하고 중복 조사를 피한다.
- **익명화 규칙 준수**: 학생 개인정보, 미공개 농장정보, 재무표 미공개 수치는 입력에 포함될 수 없다([research-routing.md](research-routing.md) §2).

## 2. 조사 순서 (순서 고정 절차)

조사 담당은 각 질문 ID에 대해 아래 1~4단계를 번호 순서대로만 수행한다.

```
[1단계: 주문서 routes 순차 탐색] (검색엔진 직행 금지)
       ↓
[2단계: 원문 페이지 직접 검증] (발행기관·자료명·연도·표/쪽·URL)
       ↓
[3단계: 즉시 스냅샷 저장 및 재현 기록] (자기 out/ 칸에만 저장, 실제 열람 상태 기록)
       ↓
[4단계: 해당 질문 미확보 시에만 공식 검색] (비공식 자료 원천 배제)
```

### 1단계: 주문서 경로 순차 탐색 (검색엔진 직행 금지)
- 주문서의 `routes` 목록에 기재된 경로를 맨 위(1순위)부터 순서대로 연다.
- **일반 검색엔진(구글·네이버 등)부터 열지 않는다.** 포털 검색으로 직행해 블로그·기사·쇼핑몰을 먼저 열람하는 것은 엄격히 금지된다.

### 2단계: 원문 페이지 실측 검증
- 해당 공식 경로의 원문 웹페이지를 직접 열어 다음 항목을 확인한다:
  - 발행기관, 자료명(보고서명 또는 통계표명), 기준연도, 표 번호 또는 페이지, 정확한 URL.
- 추측한 URL, 비공식 요약문, 블로그 재인용문은 확인 근거로 삼지 않는다.

### 3단계: 즉시 스냅샷 저장 및 재현 기록
- 원문 내용을 확인한 즉시 스냅샷을 저장하고 감사용 식별정보를 남긴다.
- **저장 위치 격리**: 논문 본문 폴더(`sources/web/` 등)에 직접 쓰지 않는다. 오직 **자기 출력 칸(`jobs/<id>/out/` 내부의 지정된 경로, 예: `out/web/`)**에만 저장한다.
- **식별 전용 출처와 열람 상태**: [source-intake.md](source-intake.md) 머리말 및 [source-identities.json](source-identities.json)에 등재된 공인 출처는 **저장 범위의 제한**(본문 스냅샷을 만들지 않고 해시·서지 식별정보만 남김)일 뿐이며 **열람 상태를 정하지 않는다.**
  - 본문 스냅샷은 계속 생략하되(해시 확보를 이유로 본문을 저장하지 않음), 해당 출처의 해시·서지 식별정보 또는 `source-identities.json`의 해당 항목을 유일하게 가리키는 연결 식별자(출처 ID/등록 키)를 남긴다.
  - 열람 상태(`본문 확인`·`서지만 확인`)는 **실제로 무엇을 열었는지**를 적는다 — 실제로 본문을 열어 확인했으면 `본문 확인`, 서지 화면만 봤으면 `서지만 확인`이다 [r12c D6b-02].

### 4단계: 제한적 검색 도구 활용 및 배제 판정
- **검색 도구 전환 조건**: "목록이 다 실패했을 때만 검색 도구"는 **그 질문이 아직 `증거 확보` 상태가 아닐 때**로 적용한다 (경로 하나가 열렸다고 해서 조사가 끝난 것이 아니다).
- 검색 시 주문서의 별칭 목록([research-sources.md](research-sources.md) §4)을 활용하되, **최소 2개 이상의 별칭**으로 확인한 뒤에만 통계 없음으로 판정한다.
- **비공식 자료 원천 배제**: 검색 결과로 나온 자료가 [source-intake.md](source-intake.md) §3의 공식 출처(정부·공공기관, 공공 통계, 학술지, 정규 교재) 밖인 비공식 자료(언론 기사, 농가 블로그, 카페, SNS, 쇼핑몰, 타인 인터뷰 등)인 경우 인용하지 않고 즉시 배제한다.
- 공식 원문을 확인하지 못하면 임의로 수치를 유추하거나 추정하지 말고 반드시 **`자료 없음`** 또는 **`확인 불가`**로 남긴다.

### 질문 최종 상태 vs 경로별 탐색 결과
- **질문 최종 상태 (질문마다 단 하나)**: 조사 완료 후 각 질문 ID에는 아래 4개 최종 상태 중 정확히 하나를 부여한다:
  1. **`증거 확보`**: 주문서의 필수 채택 조건을 모두 충족하는 공식 원문 증거를 확보함.
  2. **`조건 불일치`**: 자료를 열었으나 단위·지역·연도·상품형태 등 필수 조건이 일치하지 않음 (미확정 조건 질문인 경우 후보로 기록).
  3. **`자료 없음`**: 공식 경로 및 별칭 2종 이상 검색을 수행했으나 해당 통계/자료가 부재함.
  4. **`접근 실패`**: 링크 오류, 서버 장애, 로그인 장벽 등으로 경로 접근 자체가 불가능함.
- **경로별 탐색 결과 (경로마다 각각)**: 주문서의 각 경로(`routes`)를 열어본 결과는 경로마다 `성공` 또는 `실패`와 상세 사유를 기록한다. 하나의 질문에 대해 여러 경로를 시도하더라도, 해당 질문 전체의 최종 상태는 위의 단 하나로 결론짓는다.

## 3. 결과 서식 (단일 결과 모양)

조사 담당은 결과 파일을 자기 출력 칸(`out/`)에 작성한다.
- **질문 최종 결론을 다루는 표(① 원출처 표, ② 미확인 목록)**에는 **질문 ID**와 **질문 최종 상태** 칸을 필수로 포함한다.
- **경로별 결과를 다루는 표(③ 열어본 경로와 결과)**에는 **질문 ID**와 **경로 탐색 결과(성공/실패)** 칸을 둔다.
- **참고 표(④ 배제한 출처, ⑤ 원래 단위·조건)**는 질문 ID와 해당 표 규격 칸만 채우며 상태 칸을 요구하지 않는다.
예시 서식에 기재된 `<값>`, `<연도>`, `<URL>` 등은 이해를 돕기 위한 자리표시자이며, 실제 사실이나 통계 수치가 아니다.
**문장형 요약문, 학생용 추천 의견, 논문 작성 방향 제안은 일체 쓰지 않는다** (판단과 해석은 메인의 몫이다).

### ① 확인한 원출처 표 (다시 볼 수 있게 남긴다)
[research-routing.md](research-routing.md) §3의 기록 줄을 확장하여 조회 조건·위치·시각·스냅샷 해시(또는 식별 전용 연결)를 모두 남긴다.

| 질문 ID | 주장 (확인 사실) | 질문 최종 상태 | 확인한 원출처 | 기준연도 | 페이지·표·URL | 조회 조건 (지역·기간·필터) | 행·열 위치 | 조회 시각 | 스냅샷 파일 및 해시 (또는 식별 전용 연결) | 열람 상태 | 부가 정보 | 발견 경로 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|
| Q1 | <확인한 수치 또는 주장> | 증거 확보 | <공식 발행기관 A> | <연도> | <자료명·표번호·URL> | <조회 조건: 지역·기간·필터> | <행·열 위치> | <조회 시각> | <스냅샷 파일 경로> (sha256: <해시>) | 본문 확인 | <단위·규격·모집단 등 부가 정보> | <주문서 1순위 경로> |
| Q2 | <후보 수치 또는 주장> | 조건 불일치 | <공식 발행기관 B> | <연도> | <자료명·표번호·URL> | <조회 조건: 지역·기간·필터> | <행·열 위치> | <조회 시각> | source-identities.json:<출처 ID B> (sha256: <해시>) | 본문 확인 | <모집단·분모 부가 정보, 조건 차이 사유> | <주문서 2순위 경로> |
| Q3 | <확인한 사실 또는 수치> | 증거 확보 | <공식 발행기관 C> | <연도> | <자료명·URL> | <조회 조건: 검색 필터> | <해당 없음 또는 목차 위치> | <조회 시각> | <스냅샷 파일 경로> (sha256: <해시>) | 서지만 확인 | <문헌 서지 식별정보> | <주문서 3순위 경로> |

- **열람 상태와 식별 전용 출처 기록 의무**:
  - **열람 상태**: 실제로 무엇을 열었는지에 따라 `본문 확인`(원문 페이지·본문 표·PDF 열람) 또는 `서지만 확인`(목록·서지 화면만 열람)을 정확히 적는다.
  - **식별 전용 출처**: [source-identities.json](source-identities.json) 등재 출처는 본문 스냅샷 저장을 생략하되, 스냅샷 칸에 `source-identities.json:<출처 ID> (sha256: <해시>)`처럼 카탈로그의 해당 항목을 유일하게 가리키는 연결 식별자와 원문 해시를 반드시 남긴다 (해시를 얻으려고 본문을 저장하지 않는다). 열람 상태는 실제로 본문을 열었으면 `본문 확인`, 서지 화면만 봤으면 `서지만 확인`으로 명시한다.
  - **통계**: 모집단 및 분모 명시
  - **문헌**: 대상 및 측정 지표 명시
  - **법령**: 시행일 명시

### ② 미확인 목록
공식 원문으로 확인하지 못했거나 조건이 불일치한 질문 목록이다. 하나의 질문이 다른 표와 모순된 최종 상태로 기록되지 않는다.

| 질문 ID | 목표 지표 | 질문 최종 상태 | 미확인 사유 및 후보 내역 |

## 4. 메인의 결과 인수 및 정본 반영

조사 담당이 반환한 결과는 메인 세션이 아래 원칙에 따라 검증한 뒤 정본에 반영한다:
1. **담당 결과의 직접 인용 금지**: 담당이 반환한 마크다운 메모 자체를 논문 본문의 근거로 직접 인용하지 않는다.
2. **원문 재확인 필수**: 메인은 담당이 제시한 발행기관, 표/페이지, 핵심 숫자 및 주장을 공식 원문 페이지를 다시 열어 직접 확인한 뒤에만 `project.json` 및 본문 초안에 반영한다.
3. **스냅샷 이동**: 메인이 검증을 완료하고 정본에 채택하기로 결정한 유효 스냅샷만 논문 폴더(`sources/web/`)로 이동하여 정식 등록한다.
4. **논문 폴더 무결성 보존**: 담당은 작업 도중 논문 폴더의 어떤 파일도 직접 건드리지 못하므로, 조사가 실패하거나 중단되어도 논문 폴더의 기존 정본은 안전하게 보존된다.

## 5. 받는 쪽 검사 (수신 검사)

`gg.py delegate`의 수신 검사(앱이 분담을 켠 경우) 또는 메인 모델은 담당이 반환한 결과 표를 표별 실제 머리말 규격과 1:1로 대조하여 기계 검사한다:
1. **① 확인한 원출처 표 검사**: 표의 실제 칸인 질문 ID, 주장, 질문 최종 상태, 확인한 원출처, 기준연도, 페이지·표·URL, 조회 조건, 행·열 위치, 조회 시각, 스냅샷 파일 및 해시(또는 `source-identities.json` 유일 연결 식별자/원문 해시), 열람 상태, 부가 정보, 발견 경로가 누락 없이 채워져 있는지 검사한다.
2. **② 미확인 목록 검사**: 표의 실제 칸인 질문 ID, 목표 지표, 질문 최종 상태, 미확인 사유 및 후보 내역만 검사하며, ① 표 전용 칸(원출처·연도·URL·행열·스냅샷/해시 등)을 요구하지 않는다.
3. **③ 열어본 경로와 결과 검사**: 질문 ID, 경로 번호, 열어본 경로(기관·자료명·URL), 경로 탐색 결과(`성공`/`실패`), 상세 사유가 기재되어 있는지 확인하고, 열어본 경로 목록이 주문서의 `routes`와 일치하는지 대조한다.
4. **④ 배제한 출처 검사**: 질문 ID, 배제한 출처, 유형, 배제 사유가 채워져 있는지 검사한다 (상태 열 불요).
5. **⑤ 원래 단위·조건 검사 (수치·가격 조사 시)**: 질문 ID, 원래 단위, 포장 중량·규격, 유통 단계, 거래 조건, 원래 관측값이 채워져 있는지 검사한다 (상태 열 불요).
6. 위 표별 필수 규격 칸이 누락되었거나 서식이 깨진 경우 수령을 거부하고 미실행으로 기록한다.

> **이 검사는 빈칸·모양을 잡을 뿐 정확도를 보증하지 않는다.**
> 정확도는 4번(메인의 공식 원문 재확인)이 전적으로 맡는다.

## 6. 모델 무관 일관성

이 계약은 조사를 수행하는 모델의 종류(Opus·Sonnet·Haiku·Sol·Astra·Terra 등)나 요금제 레인과 무관하게 모든 조사 주문에 동일하게 적용된다.
- 가벼운 모델이라고 해서 검색엔진 허용, 비공식 자료 완화, 결과 서식 생략 등의 예외를 두지 않는다.
- 모든 담당은 고정된 순서(1~4단계)를 준수하고 정해진 규격 서식(①~⑤)으로만 결과를 제출한다.
