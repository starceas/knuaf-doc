# 현재 작성물 선택과 참고자료 등록

폴더 제공은 자료 열람 범위의 지정이지, 그 안의 원고를 현재 작성 기준으로 선택한 답변이 아니다. 파일 존재·수정일·파일명·내용의 완성도만으로 작목이나 이어 쓸 원고를 확정하지 않는다. 이 계약은 신규 진입, 모호한 기존 자료 가져오기, 작성 기준 변경에 적용한다.

## Q0 — 오늘 할 일

첫 말이나 이전 기록에서 목적이 분명하면 다시 묻지 않고 목적별 흐름으로 간다. 어떤 단추로 들어왔는지는 추정하지 않는다. 목적을 모를 때만 아래 카드를 한 번 보여 준다. “시작하기”처럼 목적이 없는 첫 말이면 Q1a보다 이 카드가 먼저다.

새로 쓰는 목적이 분명하면 Q1a(현재 원고)·Q1b(참고자료)를 건너뛰고 전공부터 묻는다. 참고자료는 작목이 정해진 뒤 필요할 때 한 번 묻는다. 그 밖의 목적은 Q1a부터 간다.

목적이 달라도 파일 출력 게이트는 같다. 계획 인터뷰(Q2~Q8)를 생략해도 출력은 확인된 전공·유효한 전공 연결·지원 능력을 갖춘 경로에서만 한다. 검토용 사본도 출력이다. 전공이 미확정이면 파일 출력만 보류하고 읽기·지적 목록·불일치 목록은 계속한다. 이미 확인된 전공은 다시 묻지 않으며, 표지의 전공은 학생 확인 전에는 사실로 올리지 않는다.

    [Q1-1] 오늘 할 일을 골라요
    오늘 어떤 걸 도와드릴까요?
      1) 처음부터 새로 쓰기 — 계획부터 차근차근 세워요
      2) 쓰던 원고 이어 쓰기 — 남은 부분을 채워요
      3) 원고 점검·고치기 — 점검·교수님 피드백·서식
      4) 엑셀과 숫자 맞추기 — 돈 계산과 본문 숫자 점검
      5) 아직 잘 모르겠어요 — 할 수 있는 일부터 볼게요
    → 번호로 답하거나 하고 싶은 말을 편하게 적어 주세요.

3)을 고르면 다음 선택형 질문 하나로 작업을 가른다.

    [Q1-2] 원고 고치기
    어떤 작업을 먼저 할까요?
      1) 내용 점검 — 빠진 것·틀린 것 찾기
      2) 교수님 피드백 반영 — 지적받은 부분 고치기
      3) 문서 서식 맞추기 — 표지·목차·쪽번호 정리
    → 번호로 답하거나 하고 싶은 말을 편하게 적어 주세요.

5)를 고르면 할 수 있는 일을 설명하고 끝내도 된다. 새 작성 인터뷰로 억지로 잇지 않는다.

### 목적별 질문 범위와 끝

| 목적(`intake.work_basis`) | 묻지 않는 것 | 꼭 묻는 것 | 오늘의 끝 |
|---|---|---|---|
| 새 작성 `new` | 이미 말한 항목 | 전공부터 하나씩 | 합의한 장 초안 또는 계획 정리 |
| 이어쓰기 `resume` | 원고에 이미 있는 사실, 없다고 한 참고자료 | 현재 원고(못 고르면 아래 「현재 원고를 못 고를 때」), 주인(Q1d), 다음 장에 꼭 필요한 빈칸만 | 다음 장 초안 |
| 계획 바꿔 다시 `replan` | 안 바뀐 사실 | 바뀐 것, 재사용 범위 | 바뀐 계획 반영 장 |
| 점검만 `review_only` | Q2~Q8 | 출력이 있을 때 전공 확인 | 고칠 곳 목록. 고쳐 달라고 하면 출력 게이트를 넘은 뒤에만 고친다 |
| 교수 첨삭 `prof_feedback` | Q2~Q8 | 출력 전 전공 확인, 새 결정이 필요한 첨삭 항목만 하나씩 | 지적별 [지적 → 고친 내용 → 함께 바뀐 곳] 표와 출력 게이트 통과 시 고친 사본 |
| 재무만 `finance_only` | 농장명·배경·어투·비전·실습 | 계산에 빠진 입력, [기준이 어긋날 때](workflow-order.md#기준이-어긋날-때) | 검산표, 본문 숫자 불일치 목록 |
| 서식만 `format_only` | Q2~Q8 | 출력 전 전공 확인, 표지 학적 정보 빈칸만 | 할 수 있는 서식 처리와 한글에서 학생이 직접 할 일 체크리스트 |

## Q1a — 현재 작성물

한 질문으로 먼저 묻는다.

> 지금 이어서 작성하거나 검토할 논문 원고나 재무 엑셀이 있나요? 있다면 각각 **파일명과 위치를 알려주시거나 파일을 첨부**해 주세요. 예전에 만든 초안이나 참고용 파일과 구분해 주세요. 현재 작성물이 없다면 ‘없음’이라고 해도 됩니다.

논문과 엑셀은 별개로 기록한다. 엑셀만 현재 작업물이고 논문은 예전 초안일 수 있다. 파일명만 있고 위치가 불명확하면 이미 제공된 폴더에서 후보를 찾고, 같은 이름이 여럿이면 경로를 보여 선택받는다. 폴더만 답하면 파일 목록·크기·수정일 등 최소 정보로 후보를 제시할 수 있지만 자동 선택하지 않는다. ‘가장 최근 파일’ 같은 사용자의 명시적 선택 기준도 결과 파일을 보여 확인한다.

### 현재 원고를 못 고를 때

학생이 현재 원고를 못 고르면, 학생이 열람을 허용한 범위에서 필요한 후보만 읽는다. 후보마다 작목, 이미 써 있는 장, 서로 다른 계획값(예: 면적·자금)을 한두 줄로 비교하고, 한 후보씩 “이 파일이 지금 쓰고 있는 원고 맞아요?”라고 확인한다. 비교는 선택을 돕는 자료일 뿐 자동 채택 근거가 아니다.

그래도 모르겠다면 비교 결과를 그대로 주고 현재성에 의존하는 이어쓰기·수치 반영·원고 수정은 보류한다. “새로 시작” 같은 특정 문구만 탈출구로 요구하지 않는다. Q1 질문 1회+도움 1회 한도를 지킨다.

## Q1b — 참고자료

현재 작성물 질문과 분리해 다음에 묻는다.

> 참고할 농업자료나 관련 자료가 있나요? 재배 매뉴얼·시세·학교 작성요령·선배 논문 등이 있는 **폴더 경로**를 알려주세요. 개별 파일이나 첨부도 괜찮고, 없으면 ‘없음’이라고 해도 됩니다.

여기서 받은 폴더는 참고자료 인덱스로 등록한다. 안에서 발견한 논문·엑셀은 참고 후보이며 현재 작성물로 승격하지 않는다. 하위 모델에도 ‘참고용, 현재 계획의 사실 아님’을 전달한다. 아직 작목이 정해지지 않았으면 폴더 목록만 만들고 작목을 추정한 대량 조사·전문 해석은 시작하지 않는다.

## Q1c — 작성 기준 확인

사용자가 지정한 현재 작성물 후보만 필요한 범위로 읽어 짧게 확인한다. 읽기·해석 배정은 [model-routing.md](model-routing.md)를 따른다. 후보 내용은 확인 질문의 재료이지 학생의 확정 사실이 아니다.

> 현재 원고는 `병풀_초안.docx`, 재무 파일은 ‘없음’으로 받았어요. 원고는 병풀 재배 계획을 다루고 있어요. 이 원고와 계획을 지금 기준으로 이어 쓸까요, 아니면 예전 초안이라 새 계획으로 시작할까요? 바뀐 부분이 있으면 함께 알려주세요.

파일명/위치, 원고의 작목·주제, 이어쓰기/새 작성/검토/머리말만 재사용 목적, 오래되었거나 바뀐 핵심 계획만 확인한다. 모든 숫자를 다시 묻는 인터뷰가 아니다. 사용자가 이미 파일·현재성·작업 목적을 명확히 확정했다면 그 답변을 재사용하고 기계적으로 같은 확인을 요구하지 않는다. 원고 내용이 명시한 계획과 충돌하면 해당 차이만 확인한다.

‘없음’이면 신규 인터뷰로 진행한다. 참고 폴더의 초안을 대신 채택하지 않는다. 여기서 확인하는 작목·주제는 **지정한 원고에서 읽은 것**이다 — 원고가 없으면 Q1c에서 작목·주제를 새로 묻지 않고, 기본 계획 질문([interview-guide](interview-guide.md) Q2)에서 **전공(학과 소속)부터** 정한다. 작목은 전공·자금·지역으로 좁힌 뒤에 정한다. 답변이 모호하거나 확인 대기면 현재성에 의존하는 이어쓰기·초안 생성·작목별 조사·재무 값 반영·절 역추출/import는 보류한다. 파일 목록 작성, 원답변 저장, 무관한 질문 등은 가능하다. 무응답은 동의가 아니다.

### Q1c-1 — 머리말만 재사용

앞선 논문의 **Ⅰ장 머리말(서론)만** 참고·재사용하고 Ⅱ~Ⅵ은 새로 쓰는 목적이다. 이어쓰기와 구분해 확인한다.

- 재사용할 파일·해시와 범위(문장 그대로 / 구성·문체만 / 일부 문단)를 확인한다. 범위가 불명확하면 파일을 보여 주고 문단 단위로 고른다.
- 재사용 문장의 작목·지역·규모·경험·시설은 현재 원답변과 대조한다. 사실이 다르면 그 문장을 고치거나 새로 쓰며, 과거 논문의 사실을 현재 계획으로 승격하지 않는다.
- 재사용한 머리말도 사실 검토·윤문·장 간 일관성 검토 대상이다. Ⅱ~Ⅵ은 재사용하지 않는다.
- `intake.work_basis`에 `머리말만 재사용`, 재사용 범위, 대상 파일 해시를 함께 기록한다.

## Q1d — 자료 주인 확인

파일이 하나든 여럿이든 폴더째든, 파일 주인이 이전 답변에서 명확히 드러나지 않으면 각 후보 파일마다 "본인 / 선배·타인 / 학교 견본·양식"인지 확인한다.

> 제공해주신 파일 중 `xxx.docx`와 `yyy.xlsx`가 있어요. 각 파일이 ① 본인이 직접 작성하던 파일인지, ② 선배나 다른 사람의 참고 파일인지, ③ 학교에서 배포한 견본·서식 양식인지 알려주세요.

- **파일 안 이름은 주인 판정 근거가 아니다**: 파일 메타데이터·문서 표지·엑셀 시트 머리글에 적힌 이름은 과거 견본 작성자일 수 있으므로(예: [dairy/README.md](dairy/README.md) 학교 엑셀 견본 작성자명 주의), 파일 안 이름만으로 소유자를 단정하지 않는다.
- **원답변 연결 및 승격 금지**: 답변은 원답변으로 기존 intake 출처·파일 해시와 묶어 보존한다. 답은 그 출처 기록의 `file_owner`(`self`·`other`·`sample`)와, 파일 안에 적힌 작성자 이름은 `author_names`(목록)로 남긴다. 미답변 파일의 내용이나 "선배·타인 / 학교 견본"으로 확인된 파일의 값은 학생 본인의 계획 사실로 승격하지 않는다.
- **수정·파생 파일의 승격 주의**: 학교 견본이나 타인의 파일을 학생이 일부 고쳐 쓰는 경우, `file_owner: self`라고 답했더라도 파일 전체 내용을 본인 사실로 일괄 승격하지 않는다. 학생 본인의 성명·농장 현황·계획 수치는 원답변 및 본인 증거와 직접 대조해 확인한 항목만 fact로 등록한다.

## Q1 자료 처리

- 학생이 정한 작업폴더가 있으면 그 위치를 유지한다. 없으면 “시작하기”의 기존 규칙대로 정하고, 원고 폴더 옆에 새 작업폴더를 무조건 만들지 않는다.
- 원고 파일 하나만 선택한 경우, 정본이 없으면 정한 작업폴더에 `init`한 뒤 그 파일 하나만 선택해 [자료 투입과 조사 투명성](source-intake.md)의 `source-scan`→`source-resolve`→`source-register` 흐름으로 보존 사본을 등록한다. 파일을 여러 개 고르지 않았으면 다른 파일은 등록하지 않고, 폴더 전체 `import`도 사용하지 않는다.
- 이미 받은 현재성·작업 목적 답변은 재사용한다. 파일 주인은 Q1d 규칙을 따르며, 의미가 아직 정해지지 않은 부분만 묻거나 보류한다.
- 기존 프로젝트 전체를 가져올 때는 “시작·재개”의 오프라인 확인·잠금·마이그레이션 규칙을 그대로 적용한다. 파일 하나 등록의 예외를 전체 가져오기에 넓히지 않는다.
- 보존 사본은 등록할 때 디스크에 저장된 파일 바이트를 기준으로 한다. 원본 변경 감지와 해시 대조 규칙을 유지하고, 사본이므로 동시에 저장해도 문제없다고 말하지 않는다.
- 학생에게는 `project.json`·정본·`import`·프로세스·잠금 같은 내부 말을 쓰지 않는다. 예: “원본 파일은 안전하게 그대로 두고, 복사본을 따로 만들어 거기서 이어 쓸게요.”

## 기록·재개·변경

- 원답변은 파일로 보존하고 [mid-work-questions.md](mid-work-questions.md)의 기존 질문·사실 계약으로 연결한다. 안정된 field ID는 `intake.current_manuscript`, `intake.current_finance`, `intake.reference_materials`, `intake.work_basis`를 사용한다. 역할별 없음·모름·거부를 구분하며 한 질문으로 받은 답도 역할별로 기록한다.
- 선택 파일은 출처 ID·실제 경로·해시, 작업 목적과 현재성에 대한 원답변 위치를 연결한다. 후보 파일에서 읽은 계획과 사용자가 확인한 계획을 구분한다. 확인된 선택/작성 목적은 기존 `project.json.facts` 계약으로 기록하고 별도 승인 JSON이나 두 번째 상태 정본을 만들지 않는다. 학생의 선택 확인은 내용 정확성·학교 준수·교수 승인이 아니다.
- 질문 1회+도움 1회 한도와 결정 버전을 유지한다. Q1 분리로 이미 받은 답변이나 소진된 질문 횟수를 초기화하지 않는다. 예전 ‘자료 없음’이 어느 역할까지 뜻하는지 명확하면 그대로 재사용하며, 범위가 불명확한 부분만 확인한다.
- 사용자가 현재 작업폴더로 명시한 기존 프로젝트를 재개하면 기록된 선택과 원답변을 재사용한다. 참고 폴더 안에 `project.json`이 있다는 이유만으로 그 프로젝트를 선택하지 않는다. 원고 해시 변경은 관련 검토에 반영하되 동일 파일의 통상 편집만으로 매번 현재성을 되묻지 않는다.
- `gg.py import`는 폴더 전체와 그 안의 절을 가져오는 기능이다. 참고자료와 옛 초안이 섞인 폴더를 통째로 import하지 않는다. 개별 현재 파일만 선택받았다면 그 파일만 별도 작업 사본으로 추출·등록한다. 전체 프로젝트 가져오기는 사용자가 이어갈 프로젝트 폴더로 지정한 범위에만 사용한다.
- 잘못 채택한 초안이 있으면 생성물과 기록을 보존하고 해당 초안에 의존한 계획·수치·검토를 미확정으로 분리한다. 실제 현재 파일/새 계획을 확인한 뒤 영향을 받는 부분만 갱신한다. 원본이나 무관한 답변을 삭제하거나 전체 인터뷰를 초기화하지 않는다.

이 문서는 대화·위임 시 지킬 선택 규칙이다. 저수준 CLI 자체가 사용자 의도를 자동 판정하거나 모든 직접 호출을 기술적으로 차단한다고 주장하지 않는다.
